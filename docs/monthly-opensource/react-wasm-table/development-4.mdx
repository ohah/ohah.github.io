# 3-4. 모바일 터치 수명과 배포 준비 <Badge type="info">2026-03-10</Badge>

## 손가락을 움직이기 전에 상태가 사라졌다

모바일 스크롤이 끊기던 원인은 렌더링 속도보다 이벤트 상태의 수명에 있었다. `touchstart`가 React 재렌더링을 일으키면 effect 정리가 `detach()`를 호출했다. 이때 터치 상태를 지워서, 뒤이어 도착한 `touchmove`가 시작 위치를 찾지 못했다.

3월 9일 KST 반영한 수정은 이벤트 핸들러를 분리했다 붙이는 동안 `touchState`를 유지한다. 후속 정리에서는 `detach()` 가드를 단순하게 만들고, detach·attach를 거친 뒤에도 상태가 남는 회귀 테스트를 추가했다. 이 변경은 터치 이벤트 연속성을 복구하는 수정이다. 별도의 모바일 기기 프레임 속도 측정 결과를 뜻하지 않는다. [터치 상태 보존](https://github.com/ohah/react-wasm-table/commit/e16d1dc693e00f75f54990bd1e05578e51189a6d), [회귀 테스트](https://github.com/ohah/react-wasm-table/commit/3da69f07a2b722f8c4b351714c7d62587d3a93fa)

## 배포할 수 있는 경로와 실제 배포는 별개

3월 10일 KST에는 GitHub Release 생성 또는 수동 실행으로 npm 배포를 시작하는 워크플로우를 추가했다. 이어 Node 설치 단계를 별도로 두는 대신 Bun 환경에서 `bunx npm publish`를 실행하도록 바꿨다. [배포 워크플로우](https://github.com/ohah/react-wasm-table/commit/909a8758bd161ef4a0a9c13f769d93929086d204), [Bun으로 실행](https://github.com/ohah/react-wasm-table/commit/7317ba2053e3eb545db8b96b5e890c97da96e9fd)

2026-09-26 확인 시 공개 GitHub Release 목록은 비어 있고, npm 레지스트리의 `@ohah/react-wasm-table` 조회도 404를 반환한다. 저장소의 `0.1.0` 버전 문자열과 publish 워크플로우만으로 배포 완료를 주장할 수 없다. 현재 기록은 배포 준비까지다. [GitHub Releases](https://github.com/ohah/react-wasm-table/releases), [npm 레지스트리 조회](https://registry.npmjs.org/@ohah%2Freact-wasm-table)

## 초기 실험 수치의 범위

앞선 개발기의 행 수·FPS·커밋 수는 초기 개발 당시의 기록이다. 이번 후속에서는 그 수치를 재측정하지 않았다. Canvas·WASM 구조라는 이유만으로 모든 DOM 테이블보다 빠르거나 모든 모바일 환경에서 같은 프레임 속도를 낸다고 일반화하지 않는다. 이번에 확인한 것은 터치 상태 보존과 그 회귀 테스트, 배포 자동화 코드다.
