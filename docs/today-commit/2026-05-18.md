## 요약 (AI 작성)

zntc는 전날에 이어 Module Federation을 다듬었습니다. 정적 `import "remote/x"`에 P3 검증을 통합하고([#3464](https://github.com/ohah/zntc/pull/3464)), `shareStrategy`·`strictVersion` config 표면과 `strictVersion` 빌드 시점 실패 처리([#3465](https://github.com/ohah/zntc/pull/3465), [#3466](https://github.com/ohah/zntc/pull/3466)), expose의 CSS 에셋을 manifest에 게시하는 작업([#3470](https://github.com/ohah/zntc/pull/3470)), 같은 remote를 여러 번 import할 때 무결성 검사·경고를 한 번만 하는 dedup([#3473](https://github.com/ohah/zntc/pull/3473))을 병합했습니다. shared마다 named share scope를 지정하는 config와 컨테이너 init의 다중 scope 해석, interop 테스트로 named scope 다중 지원을 마무리했고([#3476](https://github.com/ohah/zntc/pull/3476), [#3477](https://github.com/ohah/zntc/pull/3477), [#3478](https://github.com/ohah/zntc/pull/3478)), 발행된 `@zntc/core`가 `zntc.config`의 mf 설정을 네이티브로 넘기지 않던 문제를 고쳤습니다([#3483](https://github.com/ohah/zntc/pull/3483)). MF seam은 옵션 레이어에서 번들러의 단일 적용점으로 옮겼고([#3487](https://github.com/ohah/zntc/pull/3487)), 실행 예제 앱과 한·영 사용자 가이드([#3485](https://github.com/ohah/zntc/pull/3485), [#3486](https://github.com/ohah/zntc/pull/3486))를 더해 로드맵의 MF 지원 상태를 미지원에서 부분 지원으로 고쳤습니다([#3488](https://github.com/ohah/zntc/pull/3488)). 런타임 동적 remote는 빌드 검증이 어렵다는 한계도 문서에 적었습니다.

정규식 쪽에서는 AST를 패턴 텍스트로 되돌리는 printer를 추가하고([#3500](https://github.com/ohah/zntc/pull/3500)) `regex_lower`의 임시 순회를 parse, AST 변환, printer 경로로 바꿨습니다([#3505](https://github.com/ohah/zntc/pull/3505)). 이 위에서 u 플래그 다운레벨로 astral 문자를 담은 긍정·부정 문자 클래스를 surrogate 대안으로 풀고([#3514](https://github.com/ohah/zntc/pull/3514), [#3516](https://github.com/ohah/zntc/pull/3516)), i와 u를 함께 쓸 때 simple case-fold 등가 확장([#3518](https://github.com/ohah/zntc/pull/3518))을 넣었습니다. 고정 크기였던 named group·backref 버퍼를 `SmallVec`로 바꾸고([#3502](https://github.com/ohah/zntc/pull/3502)), parse 오류 경로의 메모리 누수도 막았습니다([#3506](https://github.com/ohah/zntc/pull/3506)).

RN 릴리스 번들 안정화 PR 두 개([#3480](https://github.com/ohah/zntc/pull/3480), [#3494](https://github.com/ohah/zntc/pull/3494))는 CJS export 정보 보존, automatic JSX runtime 사용, Metro와 같은 소스 확장자 순서, 워크스페이스 심링크의 논리 경로 유지, minify 시 미해결 전역과 최종 re-export import 이름 예약, CJS default interop 표식 보존 같은 수정을 묶어 병합했습니다. 비인라인 CJS import 이름 충돌 수정 [#3519](https://github.com/ohah/zntc/pull/3519)도 이날 열렸습니다. 이 밖에 es5 class async 메서드의 optional chaining 임시 변수 hoist 누락([#3467](https://github.com/ohah/zntc/pull/3467)) 수정, config·NAPI 옵션을 CLI 플래그로 노출하고 `--version`·`--no-config`·`--color`를 추가한 CLI 작업([#3489](https://github.com/ohah/zntc/pull/3489), [#3490](https://github.com/ohah/zntc/pull/3490)), 인라인 테스트를 `*_test.zig` 파일로 분리하는 테스트 배치 정리([#3498](https://github.com/ohah/zntc/pull/3498))가 있었습니다. 로드맵에는 NativeWind, RN CLI+MCP와 Chrome CDP 검증, Hermes 타깃 다운레벨 계획을 추가했고, 공개 API 레퍼런스의 JSDoc을 영어로 바꾸고 라이브러리 빌드 레시피를 썼습니다.

suji는 state에 이은 두 번째 공식 플러그인으로 SQLite를 추가하고 모바일 백엔드와 iOS·Android 예제 앱 변형까지 만들었으며, `@suji/plugin-state-node`·`@suji/plugin-sqlite-node` 래퍼로 4개 언어 SDK 구성을 채웠습니다. Electron API 대응으로 `session.clearStorageData`, `desktopCapturer.getSources`와 썸네일 캡처, 영역 지정 `capturePage`, `powerMonitor`의 locked 상태, macOS 딥 링크용 Info.plist 자동화, TIFF 클립보드, 응답 없는 `webRequest` 리스너의 timeout 폴백이 들어갔습니다. 보안 쪽은 renderer 권한 allowlist를 shell·dialog로 넓히고, Tauri와 같은 형태의 모바일 권한 게이트를 C ABI 코어(Stage 1)와 iOS·Android 호스트 글루(Stage 2)로 구현했으며, 캡처·인쇄의 경로 쓰기 명령을 fs 샌드박스로 묶었습니다. zig 핸들러 스키마에서 `.d.ts`를 생성하는 `suji types` 명령도 추가했습니다. 블로그 저장소 ohah.github.io의 커밋 12개는 크론의 문서 점검 표시와 요약 갱신 커밋입니다.
