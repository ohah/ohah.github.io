## 요약 (AI 작성)

zntc는 이날 PR 70여 개를 병합하며 여러 갈래로 나아갔습니다. 먼저 커진 파일을 나눴습니다. `emitter.zig`, `bundler_test.zig`, `codegen_test.zig`를 폴더로 쪼개고([#825](https://github.com/ohah/zntc/pull/825)), React Fast Refresh와 클래스·데코레이터 변환, linker 메타데이터 빌드를 별도 파일로 옮겼습니다([#826](https://github.com/ohah/zntc/pull/826), [#827](https://github.com/ohah/zntc/pull/827)). 기능으로는 `--outbase`·`--packages=external`·`--drop-labels` 등 CLI 옵션 13개([#829](https://github.com/ohah/zntc/pull/829)), SWC 호환 `emitDecoratorMetadata`([#832](https://github.com/ohah/zntc/pull/832), [#833](https://github.com/ohah/zntc/pull/833)), 모듈 하나를 출력 파일 하나로 내는 `--preserve-modules`([#835](https://github.com/ohah/zntc/pull/835)), 설정 파일 옵션 확장과 JS Build API([#837](https://github.com/ohah/zntc/pull/837))가 들어왔고, 모든 에러 경로가 0이 아닌 종료 코드를 돌려주게 했습니다([#838](https://github.com/ohah/zntc/pull/838)). 시맨틱 에러가 있어도 tsc처럼 출력을 내고([#842](https://github.com/ohah/zntc/pull/842)), private name의 읽기·쓰기 검사를 정밀하게 다듬었습니다([#857](https://github.com/ohah/zntc/pull/857)).

wasm32-wasi 트랜스파일 모듈과 `@zts/wasm` 패키지를 만들고([#839](https://github.com/ohah/zntc/pull/839)), CLI 트랜스파일 옵션 전체를 WASM에 바인딩했습니다([#849](https://github.com/ohah/zntc/pull/849)). 이를 바탕으로 Astro Starlight 문서 사이트와 WASM Playground를 세웠고([#841](https://github.com/ohah/zntc/pull/841)), 한국어·영어 i18n과 SWC 스타일 풀스크린 Playground([#845](https://github.com/ohah/zntc/pull/845)), Tailwind 기반 커스텀 페이지로 옮긴 Playground v3([#854](https://github.com/ohah/zntc/pull/854)), ECharts 성능 벤치마크 페이지와 TypeDoc API 레퍼런스([#858](https://github.com/ohah/zntc/pull/858)), Monaco 에러 마커와 Plugin Context API([#863](https://github.com/ohah/zntc/pull/863))가 이어졌습니다. Starlight CSS가 Monaco 커서·드래그를 깨뜨리던 문제는 여러 PR에 걸쳐 고쳤고, WASM 에러 메시지에는 줄·열과 소스 코드를 함께 보여 줍니다([#864](https://github.com/ohah/zntc/pull/864), [#865](https://github.com/ohah/zntc/pull/865)).

후반에는 bungae dev 서버와 연동하는 dev 모드와 HMR에 매달렸습니다. `--dev` 플래그와 RN에 맞춘 HMR 런타임([#867](https://github.com/ohah/zntc/pull/867))에서 출발해 자체 모듈 레지스트리에 CJS 호환 factory 인자, 의존성 맵, lazy evaluation 등을 차례로 붙였다가, CJS/ESM 상호 운용과 순환 참조 문제 때문에 dev 모드를 프로덕션 파이프라인으로 옮겼습니다([#884](https://github.com/ohah/zntc/pull/884)). 이어 모든 ESM 모듈을 `__esm`으로 감싸고 HMR hook과 `import.meta.hot` 변환을 넣었으며([#885](https://github.com/ohah/zntc/pull/885), [#886](https://github.com/ohah/zntc/pull/886)), React 컴포넌트 모듈의 `hot.accept()` 자동 삽입, 바뀐 모듈만 보내는 `--watch-json` diff, direct eval로 흰 화면을 없앤 수정, react-refresh 런타임 자동 주입과 Metro의 `__ReactRefresh` 호환([#888](https://github.com/ohah/zntc/pull/888)~[#898](https://github.com/ohah/zntc/pull/898))까지 이어졌습니다.

bungae는 이에 맞춰 Metro HMRClient 인터페이스를 구현한 ZTS 전용 HMR 클라이언트를 만들고, RN 내부의 상대 경로 require까지 바꾸도록 HMRClient 교체를 플러그인 onLoad hook으로 옮겼습니다.

공개 커밋 94개, 해당일 생성 또는 병합된 PR 72개를 정리했습니다. PR 생성 72개·병합 72개는 같은 PR이 양쪽에 포함될 수 있습니다.
