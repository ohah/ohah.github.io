## 요약 (AI 작성)

zntc는 증분 빌드 개선 시도를 두 차례 닫는 것으로 시작했습니다. 증분 빌드에서 `ModuleGraph`를 재사용하는 PoC는 이전 빌드 Linker가 해제한 메모리를 다음 빌드가 읽어 segfault가 나 NO-GO로 닫았고([#3937](https://github.com/ohah/zntc/pull/3937)), 대안인 chunk 단위 emit 캐시도 API 뼈대([#3938](https://github.com/ohah/zntc/pull/3938))까지 넣은 뒤 PoC가 잡음 수준이거나 회귀여서 닫았습니다([#3939](https://github.com/ohah/zntc/pull/3939)). 근본 해결은 빌드 간 메모리 소유권을 다시 설계하는 일이라 보고 lifecycle scope 재설계 RFC #3940을 병합했습니다([#3940](https://github.com/ohah/zntc/pull/3940)).

이후 하루 대부분은 RFC #3940의 하위 PR이었습니다. 측정 기반으로 `ProfileSnapshot` API와 증분 빌드·SSE 이벤트의 단계별 기록, dev 서버 HMR 벤치마크의 단계 분해, `WatchHandle`의 link 하위 단계 시간을 추가했습니다([#3942](https://github.com/ohah/zntc/pull/3942)부터 [#3947](https://github.com/ohah/zntc/pull/3947)). transpile 경로는 parser·transformer arena를 나눈 뒤([#3941](https://github.com/ohah/zntc/pull/3941)) `Transformer.initFromOwnedAst`로 AST 소유권을 넘겨 복제를 없앴는데([#3948](https://github.com/ohah/zntc/pull/3948), [#3952](https://github.com/ohah/zntc/pull/3952)), 87MB 합성 입력에서 peak 메모리는 RFC 추정치(-33%)에 못 미치는 84MB(-2.6%) 감소였습니다. 번들러는 `SymbolID` 타입과 `RenameTable`을 새로 두고([#3954](https://github.com/ohah/zntc/pull/3954), [#3956](https://github.com/ohah/zntc/pull/3956)) emitter, `computeMangling`, `syntheticName`, esm_wrap 헬퍼, carry-over가 이 표를 읽도록 단계적으로 바꾼 끝에 `Symbol.canonical_name` 필드를 없애 rename 정보를 한 곳으로 모았습니다([#3959](https://github.com/ohah/zntc/pull/3959)부터 [#3968](https://github.com/ohah/zntc/pull/3968)). 다중 패스 capture의 낡은 인덱스 문제도 근본 수정했습니다([#3969](https://github.com/ohah/zntc/pull/3969)).

저녁에는 mangler의 식별자 slot 할당을 liveness 기반 그래프 색칠에서 esbuild식 scope 중첩 방식으로 바꿔([#3970](https://github.com/ohah/zntc/pull/3970)) typescript.js의 `--minify-identifiers`가 약 35초에서 128ms로 줄었고, 출력은 기존과 바이트 단위로 같았습니다. test262 스위트를 결정적으로 만들고([#3964](https://github.com/ohah/zntc/pull/3964)) lib·exe 테스트 바이너리를 직렬 실행해 CI의 간헐 실패를 없앴으며([#3971](https://github.com/ohah/zntc/pull/3971)), 공유 namespace 변수 이름을 모듈 순서로 결정하고([#3972](https://github.com/ohah/zntc/pull/3972)) 해석되지 않은 import 진단이 두 번 찍히던 문제를 고쳤습니다([#3974](https://github.com/ohah/zntc/pull/3974)).

suji는 PR 없이 커밋으로 작업했습니다. macOS·Linux 리치 알림 액션, `SujiCore`를 통한 창 API 노출, 공개 C 백엔드 ABI 헤더, 선택형 Lua 백엔드 런타임, 플러그인 source 명세와 권한, 모바일 HTTPS CA 번들 주입, Unix 릴리스 산출물에 libnode 포함, create-suji 도구 체인 매트릭스, CLI 설정 로딩 리팩터링을 추가했고, Electron 이전 경로와 SDK 퍼블리시 준비 상태, isolated world 제약을 문서로 정리했습니다. 블로그 저장소 ohah.github.io에는 크론의 MDX 맞춤법 점검 커밋 2개와 일일 요약 갱신 커밋 1개가 있었습니다.
