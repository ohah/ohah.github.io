## 요약 (AI 작성)

maru는 이모지 표시를 집중적으로 다뤘습니다. 전날 열린 [#255](https://github.com/ohah/maru/pull/255)로 컬러 이모지를 atlas RGBA 그대로 그리게 한 뒤, VS16 표현과 기본 이모지 폭([#256](https://github.com/ohah/maru/pull/256), [#257](https://github.com/ohah/maru/pull/257)), 스킨톤·국기 이모지를 한 셀로 묶는 grapheme 1단계([#258](https://github.com/ohah/maru/pull/258))를 넣었습니다. 그러나 이모지가 든 명령을 붙여넣으면 zsh의 폭 계산과 어긋나 명령줄이 깨지는 문제가 이어져, 스킨톤·국기·VS16 이모지의 폭을 셸과 맞추는 쪽으로 되돌렸고([#259](https://github.com/ohah/maru/pull/259), [#260](https://github.com/ohah/maru/pull/260), [#261](https://github.com/ohah/maru/pull/261)), 큰 glyph는 셀에 맞게 축소하며([#262](https://github.com/ohah/maru/pull/262), [#264](https://github.com/ohah/maru/pull/264)) 풀사이즈 이모지는 앱이 켜는 DEC mode 2027로만 쓰게 했습니다([#263](https://github.com/ohah/maru/pull/263)). 리뷰와 재점검으로 컬러 판정 단일화, mode 2027 경계 사례, 0x1F000 블록 이모지와 VS15 처리, 스크롤 바닥에서의 soft-wrap 플래그를 고쳤습니다([#265](https://github.com/ohah/maru/pull/265), [#266](https://github.com/ohah/maru/pull/266), [#272](https://github.com/ohah/maru/pull/272), [#273](https://github.com/ohah/maru/pull/273)).

이후 maru는 설정과 키 입력으로 넘어갔습니다. vttest 로컬 워크플로와 자체 응답 적합성 스위트를 문서로 정했고([#267](https://github.com/ohah/maru/pull/267)), 폰트·테마·커서용 사용자 설정 파일 로딩([#268](https://github.com/ohah/maru/pull/268))과 키바인딩 파싱([#269](https://github.com/ohah/maru/pull/269))을 넣었습니다. Home·End·Page·F1–F12 함수 키 인코딩([#270](https://github.com/ohah/maru/pull/270))을 물리 키에 연결하고 IME를 거치지 않게 했으며([#274](https://github.com/ohah/maru/pull/274), [#275](https://github.com/ohah/maru/pull/275)), PageUp·PageDown은 메인 화면 스크롤로 바꿨다가 xterm·Ghostty처럼 앱에 넘기는 것을 기본으로 하는 `input.page-keys` 설정으로 정리했습니다([#276](https://github.com/ohah/maru/pull/276), [#277](https://github.com/ohah/maru/pull/277)). Cmd+Backspace 같은 macOS 줄 편집 바인딩([#280](https://github.com/ohah/maru/pull/280))을 넣고, Cmd+←·→가 동작하도록 셸을 login shell과 `login(1)`으로 띄운 뒤([#281](https://github.com/ohah/maru/pull/281), [#282](https://github.com/ohah/maru/pull/282)) 사용자 keymap과 무관하게 편집 키를 묶는 zsh 셸 통합([#283](https://github.com/ohah/maru/pull/283))을 추가했습니다. 문서 동기화와 PR 본문에 Mermaid 다이어그램을 요구하는 규칙([#285](https://github.com/ohah/maru/pull/285))도 들어왔고, OSC 133 semantic prompt 파싱 [#286](https://github.com/ohah/maru/pull/286)은 이날 PR이 열렸습니다.

zntc는 다운레벨 정확성 수정을 이어 갔습니다. 전날 열린 numeric·bigint 프로퍼티 키 [#4247](https://github.com/ohah/zntc/pull/4247)을 병합했고, object rest 제외 키의 quote·escape·숫자 처리([#4250](https://github.com/ohah/zntc/pull/4250)), object rest의 그래프 prepass 게이트([#4252](https://github.com/ohah/zntc/pull/4252)), es2017 타깃에서 함수 파라미터·할당 대상 object rest lowering([#4255](https://github.com/ohah/zntc/pull/4255)), for-of·for-in 좌변 object rest([#4259](https://github.com/ohah/zntc/pull/4259), [#4260](https://github.com/ohah/zntc/pull/4260))를 고쳤습니다. es5에서는 식별자 안의 `\u{...}` escape([#4256](https://github.com/ohah/zntc/pull/4256))와 computed 객체 리터럴 키([#4257](https://github.com/ohah/zntc/pull/4257))를 바로잡았고, 구조 분해 할당 대상인 `super` 프로퍼티 쓰기([#4258](https://github.com/ohah/zntc/pull/4258))도 수정했습니다. 깨진 vue 최신 배포를 피하려 e2e의 vue 버전을 3.5.35로 고정했고([#4253](https://github.com/ohah/zntc/pull/4253)), rest 파라미터 관련 [#4262](https://github.com/ohah/zntc/pull/4262)는 이날 PR이 열렸습니다.

suji는 공증 제출 전에 dmg를 읽을 수 있는지 확인하는 커밋을 넣었다가 같은 날 되돌렸습니다. 블로그 저장소에는 오늘의 커밋 요약과 크론이 만든 MDX·문구 수정 커밋이 올라갔습니다.

공개 커밋 47개, 해당일 생성 또는 병합된 PR 43개를 정리했습니다. PR 생성 41개·병합 41개는 같은 PR이 양쪽에 포함될 수 있습니다.
