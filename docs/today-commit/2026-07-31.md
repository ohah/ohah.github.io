## 요약 (AI 작성)

maru는 7월 12일에 열었던 코드 에디터·git diff·포맷/린트·LSP surface 설계(Phase 0) PR [#1340](https://github.com/ohah/maru/pull/1340)을 병합했습니다. 설계는 적대 검증을 여러 차례 거치며 스스로 결론을 뒤집었습니다. 에디터 엔진은 Monaco를 기각하고 CodeMirror 6로 확정했고, PoC 3건으로 CSP 결론을 뒤집었다가 낡은 브랜치 코드를 대조했다는 사실을 확인해 CSP 결함 주장을 철회했으며, 소켓 push 스트림이 존재한다는 오인과 file-panel 진행 상태 오인 등을 정정했습니다. 그 결과 §3부터 §8을 file-panel 도크 확장 구조로 다시 쓰고, git 리뷰 UI를 우측 도크 뷰로 설계했으며, 열려 있던 사용자 결정을 계약으로 못 박았습니다.

구현으로는 도크에 뷰 스위처를 넣어 탭 바 높이에 맞추고 AI 세션 뷰를 더했고([#1731](https://github.com/ohah/maru/pull/1731)), 읽기 전용 소스 컨트롤 뷰를 붙였습니다([#1733](https://github.com/ohah/maru/pull/1733)). git porcelain v2·numstat 순수 파서와 읽기 전용 명령 조립, 별도 스레드의 git 읽기 backend, 행 모델과 목록 렌더를 쌓았고, Zig 0.16의 io 기반 프로세스 실행 때문에 목록이 "읽는 중"에 머물던 문제와 탐색기 전용 클릭이 다른 뷰로 새던 문제를 고쳤습니다. 제품 WKWebView에서 `@codemirror/merge`가 도는지 보는 MergeView 게이트와 diff 1·2·4개의 RSS·유휴 CPU 측정([#1734](https://github.com/ohah/maru/pull/1734))에 이어, 소스 컨트롤 행을 눌러 `diff.open` 브리지로 diff Term을 여는 경로가 이어졌습니다([#1739](https://github.com/ohah/maru/pull/1739)). 이 과정에서 줄 번호·스크롤·테마 파생 색을 갖추고 리뷰가 확정한 15건과 긴 파일 표시·탭 이름 문제를 고쳤으며, "브랜치에 COMMIT 됨" 섹션을 더하고 충돌·하위 모듈이 잘못 보이던 문제를 실측으로 잡았습니다([#1740](https://github.com/ohah/maru/pull/1740)).

session-host는 RX authority adapter 수명주기와 socketpair 게이트([#1728](https://github.com/ohah/maru/pull/1728), [#1729](https://github.com/ohah/maru/pull/1729)), recovery consumer core([#1730](https://github.com/ohah/maru/pull/1730))를 닫았습니다. 외부 attach TX queue와 request ID([#1735](https://github.com/ohah/maru/pull/1735)), control 응답 correlation과 증거 테스트([#1736](https://github.com/ohah/maru/pull/1736), [#1737](https://github.com/ohah/maru/pull/1737)), revoke 통합 게이트 정의와 revoke turn 취소의 whole-turn 통합([#1738](https://github.com/ohah/maru/pull/1738), [#1741](https://github.com/ohah/maru/pull/1741)), control 계약의 타입 봉인([#1743](https://github.com/ohah/maru/pull/1743)), recovery token 권위를 ledger 이후로 미루는 수정([#1744](https://github.com/ohah/maru/pull/1744)), completed drain preparation 기반([#1745](https://github.com/ohah/maru/pull/1745)), terminal cleanup 권위 결속([#1746](https://github.com/ohah/maru/pull/1746))이 병합됐습니다.

사이드바에서는 maru 인스턴스가 여럿일 때 상태줄 훅이 감쌌던 사용자 statusLine 명령이 통째로 사라지던 경합을 고치고, 적대 검증이 다시 뚫은 손실 경로까지 막았습니다([#1732](https://github.com/ohah/maru/pull/1732)). 웹 타입 검사를 전체로 넓히고 오류 51건을 고치는 PR [#1742](https://github.com/ohah/maru/pull/1742)가 열렸습니다. zntc는 tsconfig `paths` 해석이 TypeScript·esbuild와 어긋나 진단 없이 다른 모듈을 번들하던 두 결함(상대 경로 hijack, specificity)을 고쳤습니다([#4608](https://github.com/ohah/zntc/pull/4608)).

공개 커밋 74개, 해당일 생성 또는 병합된 PR 21개를 정리했습니다. PR 생성 20개·병합 20개는 같은 PR이 양쪽에 포함될 수 있습니다.
