## 요약 (AI 작성)

zntc는 `require.context` 마무리부터 했습니다. 매칭 결과를 그래프 의존성이자 tree shaking 루트로 등록하고([#1786](https://github.com/ohah/zntc/pull/1786)), ExpoApp 실행에서 드러난 IIFE 안 raw require와 `ctx(req)`가 모듈 exports를 돌려주지 않던 문제를 고쳤습니다([#1788](https://github.com/ohah/zntc/pull/1788), [#1840](https://github.com/ohah/zntc/pull/1840)). 전날 SegmentedList로 바꾼 모듈 저장소에서 worker 읽기와 main 추가가 겹치는 경합이 CI에서 드러나 `StableSegmentedList`로 근본 해결했습니다([#1789](https://github.com/ohah/zntc/pull/1789), [#1790](https://github.com/ohah/zntc/pull/1790)). type-only import 제거는 참조 횟수 기반 첫 구현이 회귀를 내 되돌림 PR까지 열었다가, 참조별 type-context 플래그를 기록하는 방식으로 다시 구현했습니다([#1793](https://github.com/ohah/zntc/pull/1793), [#1796](https://github.com/ohah/zntc/pull/1796)). IIFE 포맷의 해석되지 않은 import는 빌드 에러로 보고합니다([#1792](https://github.com/ohah/zntc/pull/1792)).

ES5 for-of에서 let을 클로저로 잡을 때 본문을 `_loop` 함수로 빼는 수정과 그 후속([#1798](https://github.com/ohah/zntc/pull/1798), [#1799](https://github.com/ohah/zntc/pull/1799), [#1809](https://github.com/ohah/zntc/pull/1809), [#1813](https://github.com/ohah/zntc/pull/1813))을 거치며, AST 노드의 태그와 데이터 variant가 어긋나는 문제를 근본적으로 막기로 했습니다. variant 타입 `addNode` 헬퍼와 debug assertion([#1801](https://github.com/ohah/zntc/pull/1801)), 정적 감사 스크립트와 CI 통합([#1803](https://github.com/ohah/zntc/pull/1803))을 넣고, 감사에서 나온 불일치를 범주별로 정리해 0으로 만든 뒤 `--strict-cosmetic` 게이트를 걸었습니다([#1810](https://github.com/ohah/zntc/pull/1810)~[#1820](https://github.com/ohah/zntc/pull/1820)). 문서 사이트는 Tauri 톤과 Biome식 정보 구조로 리뉴얼하고([#1800](https://github.com/ohah/zntc/pull/1800)) 랜딩 레이아웃과 Starlight·Tailwind 레이어 충돌을 여러 번 손봤습니다.

후반에는 Rollup 호환 `manualChunks`를 구현했습니다. 문자열 매칭([#1844](https://github.com/ohah/zntc/pull/1844)), 함수 resolver와 NAPI 브리지([#1845](https://github.com/ohah/zntc/pull/1845), [#1846](https://github.com/ohah/zntc/pull/1846)), dynamic entry 제외 정책([#1851](https://github.com/ohah/zntc/pull/1851)), rolldown과 같은 `OutputFile.imports` 메타([#1852](https://github.com/ohah/zntc/pull/1852)), `meta.getModuleInfo`와 동적 import 정보([#1853](https://github.com/ohah/zntc/pull/1853), [#1857](https://github.com/ohah/zntc/pull/1857), [#1858](https://github.com/ohah/zntc/pull/1858)), `inlineDynamicImports`의 청크 구조 일부([#1859](https://github.com/ohah/zntc/pull/1859))까지 병합하고 React·RxJS·date-fns 등 실제 라이브러리 스모크를 붙였습니다. 이 밖에 IIFE의 external과 globals 매핑([#1828](https://github.com/ohah/zntc/pull/1828)), import attributes 라운드트립([#1836](https://github.com/ohah/zntc/pull/1836), [#1838](https://github.com/ohah/zntc/pull/1838)), 래핑 모듈 간 init/exports 변수 이름 중복 제거([#1835](https://github.com/ohah/zntc/pull/1835)), JSX에서 spread 뒤 key가 올 때의 react import 주입([#1841](https://github.com/ohah/zntc/pull/1841)), 소문자 JSX 멤버 태그 `<ns.Comp/>` 해석([#1831](https://github.com/ohah/zntc/pull/1831))이 들어갔습니다.

bungae는 HMR 때 Metro 스타일 "Refreshing..." 배너와 CLI 출력을 도입하고, 초기 HMR 업데이트 시퀀스를 보내 "Downloading..." 바가 남던 문제를 고쳤으며, `EXPO_ROUTER_APP_ROOT`를 절대 경로로 넘겼습니다. Expo 폴리필 경고 패치는 넣었다 되돌리기를 반복한 끝에 ZTS 쪽 수정으로 대체해 지웠습니다. cheolsu-proxy는 데스크톱 앱의 프론트엔드 의존성을 최신으로 올리고 Monaco 에디터 테마를 공통화했으며([#334](https://github.com/ohah/cheolsu-proxy/pull/334)), Tauri mock, CI bun 버전, zustand persist rehydrate 경합 등으로 깨진 테스트를 복구했습니다([#335](https://github.com/ohah/cheolsu-proxy/pull/335)~[#338](https://github.com/ohah/cheolsu-proxy/pull/338)). ohah.github.io에는 ZTS 개발기 11편부터 14편까지와 4월 1일부터 7일 등의 오늘의 커밋 재작성이 올라왔습니다.
