## 요약 (AI 작성)

maru는 chrome의 rich 테마를 GPU로 그리는 작업을 진행했습니다. rich 토큰셋과 `chrome.theme` 설정([#445](https://github.com/ohah/maru/pull/445)), `GpuQuad`·`GpuShadow` ABI와 SDF quad 렌더 파이프라인([#447](https://github.com/ohah/maru/pull/447))을 깔고 사이드바 밴드를 quad로 그린 뒤, 모달 합성 레이어를 나눠 둥근 모달 배경([#457](https://github.com/ohah/maru/pull/457))과 테두리, 그림자 셰이더와 draw 패스([#464](https://github.com/ohah/maru/pull/464)), 화면 경계를 넘지 않는 모달 패딩을 붙였습니다. 탭 바는 hit-test와 그리기가 같은 픽셀 경계를 쓰도록 정리하고 bottom·under·over 3단 draw로 둥근 활성 탭과 gradient를 넣었다가, 사용자 요청에 따라 평평한 배경에 앰버 언더바를 두는 방식으로 바꿨습니다([#496](https://github.com/ohah/maru/pull/496)). 사이드바에는 활성 워크스페이스 앰버 막대와 카드 여백을 더했고, 탭 고정 폭과 세로 패딩, 넘칠 때의 가로 스크롤 버튼([#505](https://github.com/ohah/maru/pull/505))과 트랙패드 가로 스와이프([#514](https://github.com/ohah/maru/pull/514)), 클릭 가능한 영역의 손가락 커서도 추가했습니다. 코드 주석의 외부 도구 이름을 maru 자체 용어로 바꿨고, `metal_frame`을 `renderer` 레이어로 옮겨 중립 frame 계약을 만들었습니다([#516](https://github.com/ohah/maru/pull/516)).

후반에는 미구현 터미널 프로토콜을 점검해 채웠습니다. nvim 모드 표시가 지워지지 않던 문제를 고친 ECH([#519](https://github.com/ohah/maru/pull/519)), 포커스 이벤트 DECSET 1004([#520](https://github.com/ohah/maru/pull/520)), SGR·x10 마우스 리포팅과 그 연결([#521](https://github.com/ohah/maru/pull/521), [#523](https://github.com/ohah/maru/pull/523)), synchronized output DECSET 2026([#525](https://github.com/ohah/maru/pull/525)), kitty keyboard protocol([#526](https://github.com/ohah/maru/pull/526), [#527](https://github.com/ohah/maru/pull/527)), kitty graphics APC 파서와 RGBA·RGB 이미지 디코드·저장([#528](https://github.com/ohah/maru/pull/528), [#530](https://github.com/ohah/maru/pull/530))이 들어왔습니다. 이후 clean-room 기준에 맞춰 kitty `FlagStack`을 독립적으로 다시 쓰고 Ghostty 구조 인용을 지웠으며([#533](https://github.com/ohah/maru/pull/533)), ESU가 오지 않으면 화면이 멈추던 synchronized output에 timeout을 넣었습니다([#534](https://github.com/ohah/maru/pull/534)).

zntc는 import specifier 사용 여부 판정, wrapped 경로 메타데이터 생성, import record 병합을 O(N²)에서 O(N)으로 줄이고([#4408](https://github.com/ohah/zntc/pull/4408), [#4409](https://github.com/ohah/zntc/pull/4409), [#4410](https://github.com/ohah/zntc/pull/4410)) `export_map` 키를 구조체로 바꿨습니다([#4427](https://github.com/ohah/zntc/pull/4427)). Infinity·NaN 상수 폴딩 회귀([#4416](https://github.com/ohah/zntc/pull/4416))와 음수 리터럴 팽창([#4429](https://github.com/ohah/zntc/pull/4429)), optional catch binding 섀도잉([#4417](https://github.com/ohah/zntc/pull/4417)), 클래스 본문 strict mode 전파와 Annex B 게이트([#4418](https://github.com/ohah/zntc/pull/4418), [#4435](https://github.com/ohah/zntc/pull/4435)), config와 CLI의 머지 우선순위([#4419](https://github.com/ohah/zntc/pull/4419)), `\p{name=value}`의 값 손실([#4420](https://github.com/ohah/zntc/pull/4420))을 고쳤습니다. 번들러 진단이 ZNTC 코드와 문서 URL을 내도록 하고 빠진 오류 문서와 동기화 CI 가드를 추가했으며([#4422](https://github.com/ohah/zntc/pull/4422), [#4431](https://github.com/ohah/zntc/pull/4431), [#4433](https://github.com/ohah/zntc/pull/4433), [#4436](https://github.com/ohah/zntc/pull/4436)), 설계 문서와 코드의 차이를 일괄 정정했습니다. suji는 Electron 패리티를 이어 `flashFrame`·about·login item·contentProtection 등 app·window 메서드 묶음([#159](https://github.com/ohah/suji/pull/159)), `setPath`·로캘 등 경로·메타 API([#162](https://github.com/ohah/suji/pull/162)), `showMessageBox` 아이콘([#163](https://github.com/ohah/suji/pull/163)), `will-quit`·`open-url` 이벤트([#164](https://github.com/ohah/suji/pull/164)), 인증서 오류·로그인·클라이언트 인증서 선택 이벤트([#168](https://github.com/ohah/suji/pull/168))를 추가하고, 인증 콜백의 IO 스레드 emit UAF를 바로 고쳤습니다([#169](https://github.com/ohah/suji/pull/169)). Windows에서는 e2e를 별도 잡으로 분리하고 `suji types`, 레지스트리 Run 키 login item, `FlashWindowEx` 주의 요청([#165](https://github.com/ohah/suji/pull/165)부터 [#167](https://github.com/ohah/suji/pull/167)까지)을 지원했습니다. multi 스캐폴딩에 node 백엔드를 넣고([#173](https://github.com/ohah/suji/pull/173)) 패리티 감사·CLI 플래그·`suji.schema.json` 보안 섹션 문서를 정비했습니다. iris는 Android 런타임 벤치마크 lane을 넓히고 strict 엔진 체크섬 검증을 넣는 등 측정 경로를 정리했습니다([#40](https://github.com/ohah/iris/pull/40)). 블로그 저장소에는 오늘의 커밋 요약과 크론 교정 커밋이 올라갔습니다.
