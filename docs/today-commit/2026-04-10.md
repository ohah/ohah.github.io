## 요약 (AI 작성)

zntc는 이날 네이티브 바인딩을 중심으로 패키지 구조를 바꿨습니다. bun:ffi 기반 `@zts/ffi`를 만들었다가 기존 플러그인 런타임을 `@zts/plugin`으로, 네이티브 바인딩을 `@zts/core`로 이름을 바꾸고([#972](https://github.com/ohah/zntc/pull/972), [#973](https://github.com/ohah/zntc/pull/973)), 곧바로 C NAPI로 전환했습니다([#975](https://github.com/ohah/zntc/pull/975)). 그 위에 `buildSync()`와 워커 스레드에서 도는 비동기 `build()`([#978](https://github.com/ohah/zntc/pull/978), [#979](https://github.com/ohah/zntc/pull/979)), esbuild 스타일 JS 플러그인의 in-process 실행([#980](https://github.com/ohah/zntc/pull/980)), Vite/Rollup 플러그인 어댑터 `vitePlugin()`([#992](https://github.com/ohah/zntc/pull/992))과 async 훅, renderChunk·generateBundle 훅([#1014](https://github.com/ohah/zntc/pull/1014), [#1016](https://github.com/ohah/zntc/pull/1016)), incremental rebuild와 HMR diff를 주는 `watch()` API([#1053](https://github.com/ohah/zntc/pull/1053), [#1054](https://github.com/ohah/zntc/pull/1054))를 얹었습니다. CLI도 Rolldown처럼 Node.js/Bun 스크립트가 NAPI를 부르는 구조로 바꿨고([#986](https://github.com/ohah/zntc/pull/986)), 플러그인 호출의 libuv 워커 점유 데드락과 멀티스레드 경합 데드락을 고쳤습니다([#987](https://github.com/ohah/zntc/pull/987), [#989](https://github.com/ohah/zntc/pull/989)). define·alias부터 `BundleOptions` 전체 필드까지 NAPI에 노출했습니다([#994](https://github.com/ohah/zntc/pull/994), [#1012](https://github.com/ohah/zntc/pull/1012), [#1022](https://github.com/ohah/zntc/pull/1022), [#1023](https://github.com/ohah/zntc/pull/1023)).

번들러·트랜스파일러 기능으로는 `--jobs=N`([#970](https://github.com/ohah/zntc/pull/970)), tsconfig.json 자동 로드([#993](https://github.com/ohah/zntc/pull/993)), ES2023 타깃과 hashbang 보존·제거([#998](https://github.com/ohah/zntc/pull/998)~[#1000](https://github.com/ohah/zntc/pull/1000)), UMD/AMD 출력 포맷([#1036](https://github.com/ohah/zntc/pull/1036)), 입출력 경로가 같을 때의 덮어쓰기 검사([#1035](https://github.com/ohah/zntc/pull/1035)), Vite 호환 `import.meta.glob`([#1047](https://github.com/ohah/zntc/pull/1047), [#1049](https://github.com/ohah/zntc/pull/1049))이 들어왔습니다. 고친 버그는 nodePaths가 bare specifier에 적용되지 않던 문제([#1043](https://github.com/ohah/zntc/pull/1043)), 선언보다 앞서 쓰인 var/function이 식별자 축소에서 어긋나던 문제([#1044](https://github.com/ohah/zntc/pull/1044), [#1045](https://github.com/ohah/zntc/pull/1045)), non-null assertion 뒤 나눗셈과 함수 타입 type predicate 파싱([#1052](https://github.com/ohah/zntc/pull/1052)), `.ts` 파일 제네릭을 JSX로 읽던 문제([#1055](https://github.com/ohah/zntc/pull/1055)), ES5 변환에서 abstract·declare 메서드와 오버로드 시그니처가 빈 함수로 나오던 문제([#1056](https://github.com/ohah/zntc/pull/1056), [#1057](https://github.com/ohah/zntc/pull/1057)) 등입니다. dev 모드 `__esm`의 함수 호이스팅은 껐다가 되돌렸고([#1061](https://github.com/ohah/zntc/pull/1061), [#1062](https://github.com/ohah/zntc/pull/1062)), named re-export 소스 모듈의 init 호출 누락을 고쳤습니다([#1064](https://github.com/ohah/zntc/pull/1064)). dev 모드 import 바인딩을 namespace 접근으로 바꾸는 [#1067](https://github.com/ohah/zntc/pull/1067)은 이날 PR이 열렸습니다. NAPI·WASM·CLI 벤치마크와 CI job, 문서 사이트의 NAPI 가이드도 추가됐습니다([#1010](https://github.com/ohah/zntc/pull/1010), [#1011](https://github.com/ohah/zntc/pull/1011)).

bungae는 ZTS를 서브모듈로 들이고 subprocess 호출을 NAPI in-process 호출로 바꿨습니다. RN 프리셋이 CLI에서만 켜던 flow·jsxInJs·resolveExtensions·mainFields·configurableExports를 NAPI 옵션에 채웠고, 이후 ZTS 수정에 맞춰 서브모듈을 여러 번 올렸습니다. 지연 로딩하는 Babel 플러그인 시스템을 붙여 reanimated와 gesture handler 데모를 예제 앱에 넣었고, iPadOS 26에서 앱이 전체 화면으로 열리도록 Info.plist를 고쳤습니다.

공개 커밋 102개, 해당일 생성 또는 병합된 PR 75개를 정리했습니다. PR 생성 75개·병합 74개는 같은 PR이 양쪽에 포함될 수 있습니다.
