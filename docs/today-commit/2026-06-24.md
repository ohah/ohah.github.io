## 요약 (AI 작성)

maru는 전날 열린 [#1014](https://github.com/ohah/maru/pull/1014)로 세팅 토글이 ⌘+ / ⌘−로 바꾼 폰트 줌을 되돌리던 문제를 고치고, 종료 시 각 pane의 claude·codex 세션을 저장했다가 재시작 때 같은 session id로 이어 가는 opt-in 복원([#1015](https://github.com/ohah/maru/pull/1015))과 그 Linux 빌드 스텁을 넣었습니다. 알림 카드 호버 강조와 구분선([#1016](https://github.com/ohah/maru/pull/1016)), light-pink 프리셋([#1017](https://github.com/ohah/maru/pull/1017))과 rose-pine·tokyo-night·nord·one-dark 등 6종 추가 및 프리셋 파싱 단일화([#1019](https://github.com/ohah/maru/pull/1019))도 들어왔고, 문서의 미완 표시를 코드 현실에 맞게 정리했습니다([#1018](https://github.com/ohah/maru/pull/1018)).

오후부터는 레이어 정리를 진행했습니다. `Term`의 런타임 핸들을 inner struct로 격리하고 `TermGeneric(Rt)`로 일반화해 Term·Pane·Tab 세션 모델을 OS 중립 `src/session/`으로 옮겼고([#1022](https://github.com/ohah/maru/pull/1022)), pane hit-test와 방향 이동을 모델 연산으로 내렸습니다([#1024](https://github.com/ohah/maru/pull/1024)). [#1021](https://github.com/ohah/maru/pull/1021)과 기능 브랜치 대상 [#1023](https://github.com/ohah/maru/pull/1023)은 병합되지 않고 닫혔지만, 같은 내용의 커밋은 main에 들어 있습니다. 3차 추출로 `split_tree`·`workspace`([#1026](https://github.com/ohah/maru/pull/1026))와 `surface`·`window`·`core_command`를 session으로 옮기고 session이 app을 참조하지 못하게 하는 가드를 세웠으며([#1027](https://github.com/ohah/maru/pull/1027)), `src/runtime`으로 이름을 바꾸는 4차 안은 이름 중복 문제로 보류했습니다([#1029](https://github.com/ohah/maru/pull/1029)). 2만 줄짜리 `app_session.zig`는 분해 계획([#1030](https://github.com/ohah/maru/pull/1030))을 세운 뒤 ⌘F 찾기를 `find.zig`로([#1031](https://github.com/ohah/maru/pull/1031)), 순수 레이아웃 기하와 픽셀·셀 hit-test를 `session/layout_math.zig`로([#1032](https://github.com/ohah/maru/pull/1032), [#1038](https://github.com/ohah/maru/pull/1038)) 떼어 냈습니다.

렌더링에서는 여러 pane이 한 atlas를 순서대로 쓸 때 뒤 pane의 무효화가 앞 pane 슬롯을 깨던 문제를, shape와 place를 나누는 인프라([#1033](https://github.com/ohah/maru/pull/1033))를 거쳐 모든 pane을 한 번에 배치하는 통합 빌드([#1034](https://github.com/ohah/maru/pull/1034))로 근본 수정했고 단위 테스트를 보탰습니다. 배경색이 칠해진 공백도 단어·URL 경계로 보게 해 URL 뒤 글자가 함께 선택되던 문제([#1035](https://github.com/ohah/maru/pull/1035)), 키패드 Enter가 확인 모달을 닫지 못하던 문제([#1041](https://github.com/ohah/maru/pull/1041))도 고쳤습니다.

공개 커밋 37개, 해당일 생성 또는 병합된 PR 28개를 정리했습니다. PR 생성 27개·병합 26개는 같은 PR이 양쪽에 포함될 수 있습니다.
