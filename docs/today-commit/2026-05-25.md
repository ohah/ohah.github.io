## 요약 (AI 작성)

zntc는 오전에 번들러 경로 소유권 정리를 이어갔습니다. watch 모드에서 `ResolveCache`를 재빌드마다 초기화해 arena가 계속 커지는 것을 막고([#3756](https://github.com/ohah/zntc/pull/3756)), `putModule` OOM 롤백의 이중 해제와 끊어진 맵 항목([#3758](https://github.com/ohah/zntc/pull/3758)), NAPI 플러그인 virtual path 누수([#3761](https://github.com/ohah/zntc/pull/3761))를 고쳤습니다. 이어 `PathRef.plugin` 변형을 없애고([#3762](https://github.com/ohah/zntc/pull/3762)) 변형별 `owns_path`를 대칭화한 뒤 bool을 `Owner` enum으로 바꾸고([#3768](https://github.com/ohah/zntc/pull/3768)), `.dataurl` 페이로드 소유 구분과 별도 arena intern, 모든 변형의 OOM errdefer 회귀 테스트까지 미뤄 둔 항목 일곱 개를 차례로 병합했습니다([#3766](https://github.com/ohah/zntc/pull/3766)부터 [#3772](https://github.com/ohah/zntc/pull/3772)). `RealpathCache`를 16샤드 mutex로 나누고([#3775](https://github.com/ohah/zntc/pull/3775)) codegen·transform 하위 단계 측정 hook을 넣었으며, 벤치마크 데이터를 재측정해 갱신하고 mimalloc을 v3.3.2로 올렸습니다.

낮부터는 dev 서버 작업이 몰렸습니다. JS dev 서버의 모듈 단위 incremental HMR을 켜고([#3783](https://github.com/ohah/zntc/pull/3783)) `watch()`에 `skipInitialOutput` 옵션을 더했으며([#3787](https://github.com/ohah/zntc/pull/3787)), `WatchHandle.stop()`이 worker 스레드 종료까지 기다리게 하는 등 후속 수정이 이어졌습니다. `runServe`는 cold-start `runBundle`을 없애고 watch만으로 돌게 바꿨고([#3826](https://github.com/ohah/zntc/pull/3826)), HMR 업데이트 모듈의 sourcemap 엔드포인트([#3820](https://github.com/ohah/zntc/pull/3820))와 여러 오류를 보존하는 `WatchRebuildEvent.errors`([#3822](https://github.com/ohah/zntc/pull/3822))도 들어왔습니다. 같은 시기 BoringSSL을 Chromium 148 stable에 고정한 서브모듈로 추가하고([#3786](https://github.com/ohah/zntc/pull/3786)) 정적 라이브러리로 통합한 뒤([#3792](https://github.com/ohah/zntc/pull/3792)), Zig 바인딩과 TLS 어댑터([#3808](https://github.com/ohah/zntc/pull/3808)), `--certfile`·`--keyfile`로 켜는 dev 서버 TLS([#3817](https://github.com/ohah/zntc/pull/3817)), HTTPS·WSS e2e 테스트([#3824](https://github.com/ohah/zntc/pull/3824))까지 병합했습니다. Windows Release 빌드의 TLS 컴파일 차단은 continue-on-error로 우회했습니다([#3842](https://github.com/ohah/zntc/pull/3842)).

저녁에는 dev overlay 클라이언트를 단일 소스로 합치고([#3780](https://github.com/ohah/zntc/pull/3780)), app 파이프라인이 JS 플러그인을 통과시키게 하며([#3827](https://github.com/ohah/zntc/pull/3827)) `@zntc/web/css` 하위 export를 새로 만들었습니다([#3829](https://github.com/ohah/zntc/pull/3829)). `runAppBuild`에 기본 `css()` 플러그인을 자동으로 붙이는 변경([#3832](https://github.com/ohah/zntc/pull/3832))은 동기 dispatcher와 비동기 `cssOnLoad`가 맞지 않아 실제로 동작하지 않는 코드라는 이유로 되돌렸고([#3838](https://github.com/ohah/zntc/pull/3838)), dev CSS 파이프라인 역할을 정리하는 RFC 문서([#3833](https://github.com/ohah/zntc/pull/3833))를 여러 차례 고쳐 병합했습니다. RFC의 한 안이던 async `buildApp` 전환 PR [#3839](https://github.com/ohah/zntc/pull/3839)은 병합되지 않고 닫혔습니다. 영어 README를 추가하고 한국어판을 README_KO로 옮겼습니다([#3830](https://github.com/ohah/zntc/pull/3830)).

suji는 Windows 지원을 크게 넓혔습니다. Windows에서 Node 백엔드와 창 이벤트를 켠 뒤([#17](https://github.com/ohah/suji/pull/17)) 클립보드, 셸, 화면·다크 모드, globalShortcut, 투명도·메시지 상자, 파일 열기·저장 대화상자, 트레이, 알림을 Win32 API로 구현했고([#18](https://github.com/ohah/suji/pull/18)부터 [#25](https://github.com/ohah/suji/pull/25)), 오후에는 창 그림자, `WM_HOTKEY` 전달용 펌프 스레드, 트레이 클릭·메뉴, 디렉터리 선택, 풍선 알림 클릭 이벤트와 코드 리뷰 후속 수정, Go c-shared DLL 로딩 수정([#35](https://github.com/ohah/suji/pull/35))을 병합했습니다.
