## 요약 (AI 작성)

bungae는 Metro와 Bungae의 번들링 속도를 단계별로 재는 벤치마크를 추가한 [#17](https://github.com/ohah/bungae/pull/17)을 병합했습니다. 벤치마크 실행기와 Metro·Bungae 구현, 결과를 PR 댓글로 남기는 GitHub Actions 워크플로를 만들고, 리뷰를 반영해 인자 검증과 0으로 나누기를 막았습니다. CI에서 경로 해석이 흔들리자 중간 빌드 스크립트를 빼고 `bunx bunup`을 직접 부르게 했으며, ExampleApp 설치 단계를 지웠다가 bin 심볼릭 링크 때문에 되돌렸고, 댓글 본문은 `body-path`로 넘기고 기본 실행 횟수를 줄였습니다. CLI 코드는 `packages/bungae/cli/` 폴더로 옮기고, 소스 맵 생성의 쓰지 않는 `bundleName` 옵션을 지웠습니다.

chrome-remote-devtools는 전날 연 [#89](https://github.com/ohah/chrome-remote-devtools/pull/89)를 병합해, Rust 서버가 `Network.responseReceived`의 응답 본문을 저장했다가 `Network.getResponseBody`에 답하게 했습니다. 같은 PR에서 client 패키지 빌드를 `bun build`에서 bunup으로, 다시 sourcemap 무시 목록 지원을 이유로 tsdown으로 옮기고, 소스 맵에 ignoreList를 붙이는 후처리를 넣었습니다. 출력 파일 이름이 `index.global.js`로 바뀐 데 맞춰 서버 경로와 Tauri 리소스를 고치고, 개발 모드에서도 리소스가 빌드되도록 `beforeDevCommand`를 추가했으며, 브라우저 번들에서 동적 require 오류를 내던 rrweb 초기화를 동적 import로 바꿨습니다. 테스트는 비동기 이벤트를 응답 ID로 기다리도록 고쳤고 clippy 경고도 정리했습니다.

공개 커밋 30개, 해당일 생성 또는 병합된 PR 2개를 정리했습니다. PR 생성 1개·병합 2개는 같은 PR이 양쪽에 포함될 수 있습니다.
