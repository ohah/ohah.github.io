## 요약 (AI 작성)

maru는 창 이동성 작업의 M3 마무리와 웹 패널 Phase 4 착수가 함께 진행됐고, PR 8개가 main에 병합됐습니다. M3e는 재시작 뒤에도 활성 창 focus를 유지하도록 `maru.workspace.v1`에 선택 필드 `active-window`를 더하는 방식으로 들어갔고([#1252](https://github.com/ohah/maru/pull/1252)), 직렬화 v2로 올리던 PR [#1251](https://github.com/ohah/maru/pull/1251)은 과설계로 판단돼 병합 없이 닫혔습니다. M3f는 같은 패턴으로 창 위치·크기·모니터를 복원합니다([#1253](https://github.com/ohah/maru/pull/1253)). 리뷰에서 나온 결함 7건, 즉 복원 중 창 생성 실패 시 엉뚱한 창에 focus가 가는 문제, 전체 화면 창이 거대한 일반 창으로 복원되는 문제, 모니터 재배치 시 창이 화면 밖에 뜨는 문제 등은 [#1254](https://github.com/ohah/maru/pull/1254)에서 고쳤습니다.

웹 패널 쪽은 WKWebView나 렌더러를 건드리지 않고 패널 rect와 surface 생애주기를 순수 Zig로 계산하는 4a([#1255](https://github.com/ohah/maru/pull/1255))에서 시작했습니다. 이어 모달 렌더러의 그리기 단계를 동작 변화 없이 함수로 나눈 4b-1([#1256](https://github.com/ohah/maru/pull/1256)), 모달 오버레이를 별도 물리 `CAMetalLayer`로 떼고 contentView를 컨테이너로 바꾼 4b-2([#1257](https://github.com/ohah/maru/pull/1257)), 오버레이 present·drop 로직을 다시 설계한 리뷰 수정([#1258](https://github.com/ohah/maru/pull/1258))이 병합됐습니다. 마지막으로 빈 WKWebView를 활성 pane 본문에 터미널과 오버레이 사이 z-order로 붙이는 4c([#1259](https://github.com/ohah/maru/pull/1259))가 들어갔으며, 콘텐츠·브리지·입력 전환은 이후 단계로 남겼습니다.

공개 커밋 8개, 해당일 생성 또는 병합된 PR 9개를 정리했습니다. PR 생성 9개·병합 8개는 같은 PR이 양쪽에 포함될 수 있습니다.
