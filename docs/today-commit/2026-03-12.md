## 요약 (AI 작성)

cheolsu-proxy는 PR 서른네 개를 main에 병합하며 하루 대부분을 구조 정리에 썼습니다. 오전에는 데스크톱 `proxy_v2.rs`, 데몬 `protocol.rs`, MCP 서버 `main.rs`를 기능별 모듈로 나누고 `intercept.rs`·`session.rs`·`store.rs` 유닛 테스트를 붙였으며([#199](https://github.com/ohah/cheolsu-proxy/pull/199)부터 [#204](https://github.com/ohah/cheolsu-proxy/pull/204)), 이어 `hybrid_tls_handler.rs`·`client_handler.rs`·`tls_client.rs`·`diff.rs`·`engine.rs`·`detection.rs` 등 큰 파일을 서브모듈로 쪼개는 작업을 여러 PR로 병합했습니다([#205](https://github.com/ohah/cheolsu-proxy/pull/205)부터 [#214](https://github.com/ohah/cheolsu-proxy/pull/214)). 같은 내용을 일부만 담은 [#208](https://github.com/ohah/cheolsu-proxy/pull/208)은 닫혔습니다. 인증서 생성의 `unwrap`·`expect`를 Result와 폴백으로 바꾸고([#215](https://github.com/ohah/cheolsu-proxy/pull/215)), 데몬 컨텍스트의 채널을 묶어 깊은 중첩을 풀었으며([#216](https://github.com/ohah/cheolsu-proxy/pull/216)), macOS에서 설치한 CLI·MCP가 OpenSSL dylib를 찾지 못하던 문제를 고쳤습니다([#217](https://github.com/ohah/cheolsu-proxy/pull/217)).

오후에는 패닉 방지와 타임아웃, 바디 크기 제한, atomic ordering, graceful shutdown 등 프록시 견고성 개선([#218](https://github.com/ohah/cheolsu-proxy/pull/218), [#219](https://github.com/ohah/cheolsu-proxy/pull/219))에 이어, 정규식 캐시의 LRU 전환, 매직 넘버 상수화, `Response::builder` 헬퍼, `handle_command` 인자를 묶은 `CommandContext`, 불필요한 `.clone()` 제거 같은 작은 리팩터링 PR이 한꺼번에 병합됐습니다([#220](https://github.com/ohah/cheolsu-proxy/pull/220)부터 [#228](https://github.com/ohah/cheolsu-proxy/pull/228)). 관측성·보안·성능 종합 개선([#229](https://github.com/ohah/cheolsu-proxy/pull/229))과 테스트 헬퍼 통합·데드 코드 제거([#230](https://github.com/ohah/cheolsu-proxy/pull/230)) 뒤에는 CI에서 테스트 CA 인증서를 직접 만들고 Linux 저장소 지원과 macOS 테스트를 정리했습니다([#231](https://github.com/ohah/cheolsu-proxy/pull/231)). 저녁에는 프런트엔드 중복 제거([#232](https://github.com/ohah/cheolsu-proxy/pull/232))와 race condition·stale closure·조용히 삼키던 에러 수정([#233](https://github.com/ohah/cheolsu-proxy/pull/233))을 병합했고, Grafana Loki식 쿼리 빌더 UI와 여러 따옴표를 지원하는 쿼리 파서 커밋도 들어왔습니다. 웹소켓 메시지 표 가상 스크롤 [#234](https://github.com/ohah/cheolsu-proxy/pull/234)는 이날 열려 다음 날 병합됐습니다.

React Native 번들러 bungae는 OXC·Rolldown 기반 번들러 1단계로 Rolldown 핵심 번들링, 플랫폼 해석·Flow 제거·JSON·에셋 플러그인, 트리 셰이킹과 Hermes 바이트코드 컴파일을 병합하고([#20](https://github.com/ohah/bungae/pull/20)), 기본 번들러를 graph에서 oxc로 바꿨습니다. 이어 2단계로 Rolldown DevEngine 기반 개발 서버와 HMR, React Refresh를 넣고, Hermes가 읽지 못하는 문법을 SWC로 ES5로 낮추는 hermes-compat 플러그인과 RN 폴리필·전역 설정을 붙였습니다([#21](https://github.com/ohah/bungae/pull/21)). DevEngine HMR과 Hermes 호환을 이어 가는 [#22](https://github.com/ohah/bungae/pull/22)는 이날 열려 3월 14일에 병합됐습니다.
