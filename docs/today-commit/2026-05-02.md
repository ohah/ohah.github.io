## 요약 (AI 작성)

zntc는 React Native 빌드에서 lodash-es를 하나만 가져와도 모든 모듈이 번들에 들어가던 회귀를 먼저 고쳤습니다. `--platform=react-native`가 ESM 모듈을 `.esm`으로 감싸는 방식과 tree-shaker의 부수 효과 판단이 엉켜 `sideEffects: false` barrel이 지워지지 않던 문제로, 회귀 테스트와 함께 병합됐습니다([#2409](https://github.com/ohah/zntc/pull/2409)). 이어 tree-shaking 구현 가이드와 한·영 문서 페이지를 추가했고([#2411](https://github.com/ohah/zntc/pull/2411)), tsconfig 자동 탐색을 프로세스 단위로 캐시하는 `TsconfigCache`를 NAPI와 vite 플러그인에 넣었습니다([#2412](https://github.com/ohah/zntc/pull/2412)).

transpile의 binding-lite 경로는 하루 내내 다듬었습니다. import 생략 안전성을 보강한 뒤([#2410](https://github.com/ohah/zntc/pull/2410)) 파라미터, 함수 안 var, 함수 표현식 이름이 import를 가리는 경우를 차례로 처리해 shadow 때문에 일반 경로로 넘어가는 횟수를 줄였고([#2414](https://github.com/ohah/zntc/pull/2414), [#2419](https://github.com/ohah/zntc/pull/2419), [#2423](https://github.com/ohah/zntc/pull/2423), [#2424](https://github.com/ohah/zntc/pull/2424), [#2429](https://github.com/ohah/zntc/pull/2429)), `TransformPlan` 적중률 보고([#2421](https://github.com/ohah/zntc/pull/2421))와 comptime visitor로 묶은 함수 var 탐색기([#2427](https://github.com/ohah/zntc/pull/2427))가 들어갔습니다. 번들러는 할 일이 없는 graph 변환 사전 패스를 건너뛰고 AST의 문법 플래그로 사전 패스 진입을 O(1)에 판정하도록 바꿨으며([#2432](https://github.com/ohah/zntc/pull/2432), [#2433](https://github.com/ohah/zntc/pull/2433), [#2436](https://github.com/ohah/zntc/pull/2436)), 같은 PR에서 TS `export =`를 `module.exports =`로 내리고 minify 대상에서 보호했습니다. 메모리 결함도 여럿 잡았습니다. Flow 패턴을 막던 미초기화 메모리 두 건과 slice 재할당 뒤 옛 포인터를 쓰던 형제 지점들([#2425](https://github.com/ohah/zntc/pull/2425), [#2428](https://github.com/ohah/zntc/pull/2428)), var 호이스팅 rename slice의 use-after-free([#2434](https://github.com/ohah/zntc/pull/2434)), import_record specifier의 use-after-free로 `require()` 호출이 그대로 남던 문제([#2435](https://github.com/ohah/zntc/pull/2435))입니다. graph 탐색의 read/stat 비용 개선 [#2440](https://github.com/ohah/zntc/pull/2440)은 이날 열려 5월 3일에 병합됐습니다.

RN codegen은 상속 합성과 파일 간 참조 허용([#2415](https://github.com/ohah/zntc/pull/2415)), Flow 패턴과 cast 래퍼 해제([#2420](https://github.com/ohah/zntc/pull/2420)), `Pick`·`Omit` 유틸리티 타입과 마지막 prop 우선 중복 제거([#2431](https://github.com/ohah/zntc/pull/2431)), `CT.X` 같은 namespace 한정 타입 참조([#2441](https://github.com/ohah/zntc/pull/2441)), `T[]` 배열 표기와 중첩 객체 리터럴 prop 타입([#2444](https://github.com/ohah/zntc/pull/2444), [#2446](https://github.com/ohah/zntc/pull/2446))을 지원하게 됐습니다. 플러그인 이름은 `rn_codegen`으로 바꿨고([#2442](https://github.com/ohah/zntc/pull/2442)), `@react-native/codegen` 결과와 비교하는 스냅샷 기반을 만들어 4개 스펙 기준선을 두고 바이트 비교에서 의미 비교로 옮겼습니다([#2443](https://github.com/ohah/zntc/pull/2443), [#2448](https://github.com/ohah/zntc/pull/2448), [#2449](https://github.com/ohah/zntc/pull/2449)). 파서는 prop 위치의 Flow exact object 문법을 처리하게 됐습니다([#2450](https://github.com/ohah/zntc/pull/2450)).

bungae는 Bun이 CJS 산출물에 넣는 `import.meta.require` 폴리필 때문에 Node에서 `bungae build`가 실패하던 문제를 후처리로 고쳤고, codegen은 ZTS RN preset 기본값을 믿도록 해 `_NATIVE` 토글을 없앴으며, zts 서브모듈과 lockfile을 갱신했습니다. 블로그 저장소 ohah.github.io의 커밋 15개는 크론이 `CRON_CRD_WRITE.md` 점검 상태를 기록한 커밋 14개와 요약 추가 커밋 1개입니다.

공개 커밋 78개, 해당일 생성 또는 병합된 PR 34개를 정리했습니다. PR 생성 34개·병합 32개는 같은 PR이 양쪽에 포함될 수 있습니다.
