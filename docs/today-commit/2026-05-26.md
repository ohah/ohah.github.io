## 요약 (AI 작성)

zntc의 가장 큰 작업은 MCP였습니다. 서버의 `handleMcp` 본문을 전송 방식과 무관한 dispatcher로 분리하고([#3872](https://github.com/ohah/zntc/pull/3872)) stdio 전송과 `zntc mcp` 하위 명령을 더한 뒤([#3873](https://github.com/ohah/zntc/pull/3873)), JSON-RPC 2.0 notification에 응답하지 않도록 고치고 root 옵션과 `ZNTC_ROOT` 환경 변수를 받게 했습니다. React Native 쪽에는 dev 빌드 entry에 MCP 런타임 preamble을 자동으로 넣고([#3877](https://github.com/ohah/zntc/pull/3877)) WebView wrapper alias([#3878](https://github.com/ohah/zntc/pull/3878)), 앱 채널 WS 엔드포인트([#3879](https://github.com/ohah/zntc/pull/3879))와 런타임 WS 클라이언트([#3880](https://github.com/ohah/zntc/pull/3880)), `AppChannel.request` 응답 매칭([#3887](https://github.com/ohah/zntc/pull/3887))을 쌓아 양방향 확인용 `ping_app` 도구([#3888](https://github.com/ohah/zntc/pull/3888))와 E2E 테스트([#3891](https://github.com/ohah/zntc/pull/3891))까지 이었습니다. 저녁에는 fiber 트리를 다루는 `find_element`, `inspect_state`, `eval_code`, `get_logs`, `take_snapshot` 도구를 차례로 추가했습니다([#3892](https://github.com/ohah/zntc/pull/3892), [#3893](https://github.com/ohah/zntc/pull/3893), [#3895](https://github.com/ohah/zntc/pull/3895), [#3896](https://github.com/ohah/zntc/pull/3896), [#3897](https://github.com/ohah/zntc/pull/3897)). 그사이 수신 버퍼 크기 조정, WebView wrapper의 HMR 경쟁 조건, `DevServer.deinit`가 연결 스레드 종료를 기다리게 하는 수정([#3889](https://github.com/ohah/zntc/pull/3889)) 등 리뷰 후속 PR이 이어졌습니다.

오전에는 Windows TLS 문제의 원인을 `TlsConnection` comptime 분기로 고치고 전날의 CI 우회를 되돌렸으며([#3843](https://github.com/ohah/zntc/pull/3843)), RFC #3833의 D1a'' 1단계로 사용자가 명시한 `css({postcss})`를 호출 쪽 pre-warm으로 적용했습니다([#3844](https://github.com/ohah/zntc/pull/3844)). 2단계(dev 경로 pre-warm), 헬퍼 추출, zero-config PostCSS 이중 실행 해소, `css({root})`가 조용히 무시되던 회귀, `postcssDirDeps` 보존 수정은 스택 기능 브랜치에 차례로 병합됐고([#3845](https://github.com/ohah/zntc/pull/3845), [#3848](https://github.com/ohah/zntc/pull/3848), [#3854](https://github.com/ohah/zntc/pull/3854), [#3856](https://github.com/ohah/zntc/pull/3856) 등), 이 커밋들은 후속 이슈 다섯 건을 묶은 [#3859](https://github.com/ohah/zntc/pull/3859)와 함께 main에 들어왔습니다. 이어 native watch가 그래프 밖의 새 `.css` 파일을 감지하도록 FileWatcher 디렉터리 감시와 rescan을 넣고([#3860](https://github.com/ohah/zntc/pull/3860), [#3862](https://github.com/ohah/zntc/pull/3862)), `css({root})` 단독 지정 시 탐색 기준 경로와 drain 경로의 prepare 누락을 고쳤으며, dev-incremental PostCSS 회귀를 바로잡아 main CI를 복구했습니다([#3868](https://github.com/ohah/zntc/pull/3868)). `__zntc_modules` Proxy가 `.css` 키의 부수 효과 import를 noop으로 처리하도록 했고([#3870](https://github.com/ohah/zntc/pull/3870), [#3871](https://github.com/ohah/zntc/pull/3871)), napi 타깃에 BoringSSL을 정적 링크해 `SSL_CTX_free` 미정의 심볼 문제를 해결했습니다([#3894](https://github.com/ohah/zntc/pull/3894)).

suji는 Windows 패키징을 진행했습니다. CEF·Node 런타임을 함께 담은 self-contained 패키지와 패키징된 exe 감지([#39](https://github.com/ohah/suji/pull/39)), 백엔드·플러그인 dylib 번들링과 런타임 경로 해석([#40](https://github.com/ohah/suji/pull/40)), 리뷰 후속의 sentinel 마커와 dylib 사전 검증([#41](https://github.com/ohah/suji/pull/41)), dylib이 없으면 실패시키는 `--strict` 옵션([#42](https://github.com/ohah/suji/pull/42))을 병합했고, 같은 번들링을 macOS·Linux에도 맞췄습니다([#43](https://github.com/ohah/suji/pull/43)). Windows 자동 업데이터는 PowerShell과 `Expand-Archive`로 zip 형식을 처리합니다([#44](https://github.com/ohah/suji/pull/44)). state·sqlite 플러그인의 Windows e2e와 wrapper 테스트 러너([#36](https://github.com/ohah/suji/pull/36)), stable Rust 빌드를 위해 specta TypeScript 내보내기를 cargo feature로 분리한 Rust SDK 수정([#37](https://github.com/ohah/suji/pull/37))도 들어갔고, PR 없이 Windows CI 도구 체인을 MSYS2 libnode 기준으로 고치고 Linux GTK 대화상자 백엔드를 추가했습니다.
