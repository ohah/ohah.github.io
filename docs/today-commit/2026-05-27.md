## 요약 (AI 작성)

zntc는 오전에 BoringSSL 빌드를 손봤습니다. 정적 라이브러리에 `-fPIC`를 켜 NAPI 교차 타깃 빌드를 되살리고([#3898](https://github.com/ohah/zntc/pull/3898)), Linux에서 dlopen 시 `__ubsan` 심볼 문제를 sanitize_c 해제로 고쳤으며([#3899](https://github.com/ohah/zntc/pull/3899)), windows-msvc ia32 빌드를 `linkLibCpp` 우회로 복구했습니다([#3910](https://github.com/ohah/zntc/pull/3910)). 이어 NAPI에 BoringSSL 정적 링크 확인용 `tlsSelfCheck`([#3905](https://github.com/ohah/zntc/pull/3905)), 프로세스 안에서 HTTPS dev 서버를 띄우는 `startDevServer`·`stopDevServer`([#3906](https://github.com/ohah/zntc/pull/3906)), quiet 모드와 0번 포트 자동 할당·`getDevServerPort`([#3907](https://github.com/ohah/zntc/pull/3907))를 추가하고 일상 로그를 조용히 하되 중요한 진단은 항상 stderr로 내게 했습니다([#3908](https://github.com/ohah/zntc/pull/3908)). MCP는 `tap_element`·`get_network` 도구와 `eval_code`의 async/await 지원, 도구 문서 MCP.md까지 들어갔지만([#3903](https://github.com/ohah/zntc/pull/3903), [#3904](https://github.com/ohah/zntc/pull/3904), [#3911](https://github.com/ohah/zntc/pull/3911)), 낮에 최근 이틀 동안 추가한 MCP 코드 전체를 롤백했습니다([#3913](https://github.com/ohah/zntc/pull/3913)). HTTPS dev 서버와 SSE 이벤트 API는 남기고 MCP 구현은 백로그로 미뤘습니다.

mangler에서는 자유 변수를 정밀하게 분석해 c2 경로를 안전하게 만드는 R1-a RFC를 쓰고([#3918](https://github.com/ohah/zntc/pull/3918)) `FreeVarMap` 타입, SemanticAnalyzer의 자유 변수 수집, linker 연결을 출력에 영향 없는 형태로 병합했습니다([#3919](https://github.com/ohah/zntc/pull/3919), [#3920](https://github.com/ohah/zntc/pull/3920), [#3921](https://github.com/ohah/zntc/pull/3921)). 그러나 로컬 측정에서 zod·effect·rxjs 번들 크기가 전혀 줄지 않아 NO-GO로 종결했고([#3922](https://github.com/ohah/zntc/pull/3922)), 세 PR은 되돌렸습니다([#3923](https://github.com/ohah/zntc/pull/3923)). RFC #3833의 남은 안들에도 폐기 표시를 했습니다. 오후부터는 성능 작업으로, samply 샘플링 프로파일러 워크플로와 `-Dkeep-debug` 옵션([#3925](https://github.com/ohah/zntc/pull/3925))을 추가하고 소스 길이에 맞춰 `ast.nodes`·`ast.extra_data`, transformer용 복제 AST, `Scanner.line_offsets` 용량을 미리 잡게 했습니다([#3926](https://github.com/ohah/zntc/pull/3926)부터 [#3930](https://github.com/ohah/zntc/pull/3930)). typescript.js 9MB 기준 `ast.nodes` 사전 할당은 실행 시간을 약 2% 줄였습니다. 하루 끝에는 dev 서버 HMR 지연 재설계 RFC([#3931](https://github.com/ohah/zntc/pull/3931))와 NAPI `dev_mode` 옵션 연결로 lodash HMR을 398ms에서 307ms로 줄인 수정([#3932](https://github.com/ohah/zntc/pull/3932)), 증분 빌드에서 `ModuleGraph`를 재사용하는 RFC와 첫 API([#3933](https://github.com/ohah/zntc/pull/3933), [#3934](https://github.com/ohah/zntc/pull/3934), [#3936](https://github.com/ohah/zntc/pull/3936))가 이어졌고, CI의 bun 버전을 1.3.11로 고정했습니다([#3916](https://github.com/ohah/zntc/pull/3916)).

suji는 플러그인 네 개를 추가했습니다. 회전 파일 로거 `@suji/plugin-log`([#45](https://github.com/ohah/suji/pull/45)), 파일 기반 설정 저장소 `@suji/plugin-store`([#46](https://github.com/ohah/suji/pull/46)), URL 허용 목록을 둔 `@suji/plugin-http`([#47](https://github.com/ohah/suji/pull/47)), Windows WinRT 토스트를 쓰는 `@suji/plugin-notification-rich`([#48](https://github.com/ohah/suji/pull/48))이며, 이후 http 플러그인의 스트리밍 응답 크기 제한과 허용 목록 기반 사용자 헤더, 알림 이미지 재활성화 등 후속 PR이 병합됐습니다([#49](https://github.com/ohah/suji/pull/49)부터 [#53](https://github.com/ohah/suji/pull/53)). printToPDF·capturePage를 지연 응답으로 진짜 Promise처럼 동작하게 했고([#54](https://github.com/ohah/suji/pull/54)), Linux·Windows에서 CEF GPU 가속을 켜고 e2e 검증을 더했습니다([#55](https://github.com/ohah/suji/pull/55), [#56](https://github.com/ohah/suji/pull/56)). PR 없이 Linux GTK 트레이·메뉴 팝업, X11 전역 단축키, CEF Views 창 옵션 맞춤도 커밋했습니다.
