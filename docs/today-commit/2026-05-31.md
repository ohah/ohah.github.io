> 날짜는 UTC 기준으로 나눴습니다(9월 22일부터는 한국 시간 기준). 커밋은 커미터 시각(committer date), PR은 생성·병합 시각으로 분류했습니다. 목록은 2026-10-06 KST에 GitHub에서 다시 조회해 보강했습니다. 공개 저장소의 기본 브랜치 활동만 포함합니다.

## 요약 (AI 작성)

zntc는 하루 내내 lazy compilation을 진행했습니다. 번들러가 동적 import 경계에서 멈춰 파싱하지 않은 seed를 남기고, 그 청크는 emit을 건너뛰되 경로 기반의 안정된 이름을 갖게 한 뒤([#4053](https://github.com/ohah/zntc/pull/4053), [#4054](https://github.com/ohah/zntc/pull/4054)), `emitChunks`가 단일 청크만 내보내는 기능과 강제 파싱 primitive를 더해 dev 서버에 요청 시점 청크 라우트를 열었습니다([#4055](https://github.com/ohah/zntc/pull/4055)부터 [#4058](https://github.com/ohah/zntc/pull/4058)). 서버는 watch에 따라 lazy 청크 캐시를 무효화하고, 중첩된 `import()`의 seed를 누적하며, 그래프가 바뀌면 entry를 다시 계산하도록 했고([#4059](https://github.com/ohah/zntc/pull/4059), [#4060](https://github.com/ohah/zntc/pull/4060), [#4061](https://github.com/ohah/zntc/pull/4061)), NAPI `startDevServer`에 `lazyCompilation` 옵션을 노출했습니다([#4064](https://github.com/ohah/zntc/pull/4064)). 오전에는 linker의 mangle 경로 헬퍼를 통합하고 청크별 bitset 누수를 막는 정리도 있었습니다([#4052](https://github.com/ohah/zntc/pull/4052)).

오후에는 같은 기능을 JS 쪽으로 넓혔습니다. lazy 프리미티브를 build·watch API에 노출하고 `watch()`의 onReady·onRebuild 이벤트에 `lazySeeds`를 담았으며([#4069](https://github.com/ohah/zntc/pull/4069), [#4070](https://github.com/ohah/zntc/pull/4070), [#4075](https://github.com/ohah/zntc/pull/4075)), JS dev 서버에 요청 시점 청크 라우트와 캐시 epoch 가드를 붙인 끝에 `zntc dev --lazy` 플래그를 추가했습니다([#4073](https://github.com/ohah/zntc/pull/4073), [#4077](https://github.com/ohah/zntc/pull/4077), [#4078](https://github.com/ohah/zntc/pull/4078)). 무관한 파일을 고쳐도 cold 재빌드가 일어나지 않도록 seed 단위로 캐시를 무효화했고([#4080](https://github.com/ohah/zntc/pull/4080)), 방문한 lazy 청크를 watch 그래프에서 materialize하는 설계와 `WatchHandle.requestLazySeed()` 구현([#4081](https://github.com/ohah/zntc/pull/4081)부터 [#4084](https://github.com/ohah/zntc/pull/4084)), 깊은 파일 편집이 화면에 반영되지 않던 문제의 full-reload 대체와 브라우저 e2e([#4085](https://github.com/ohah/zntc/pull/4085))가 이어졌습니다. 밤에는 리로드 없이 상태를 보존하는 split 청크 모듈별 HMR RFC([#4086](https://github.com/ohah/zntc/pull/4086))와 그 첫 단계로 청크 모듈별 HMR 코드 수집([#4087](https://github.com/ohah/zntc/pull/4087))을 병합했습니다.

버그 수정으로는 entry 모드 dev 서버 종료 시 watch 스레드를 기다리지 않아 생기던 segfault([#4065](https://github.com/ohah/zntc/pull/4065)), keep-alive 연결 스레드 종료 시 해제 후 사용([#4067](https://github.com/ohah/zntc/pull/4067)), watch·dev lazy 경로가 동적 청크를 만들지 않던 문제([#4072](https://github.com/ohah/zntc/pull/4072)), cache-hit 재빌드가 lazy seed를 즉시 파싱·emit하던 문제([#4076](https://github.com/ohah/zntc/pull/4076))가 있습니다. 문서에는 주 설정이 자체 `zntc.config`이고 Vite·Rollup 어댑터는 호환용이라는 점을 명시했습니다([#4068](https://github.com/ohah/zntc/pull/4068)).

suji는 PR 없이 5,500줄이 넘던 `main.zig`에서 CLI 진단·사용법, `runInit`, 백엔드 빌드 헬퍼, `runTypes`와 스키마 덤프, 플러그인 로더와 패키징 경로 헬퍼, 백엔드 수명 주기를 각각 별도 파일로 분리했습니다.

공개 커밋 36개, 해당일 생성 또는 병합된 PR 30개를 정리했습니다. PR 생성 30개·병합 30개는 같은 PR이 양쪽에 포함될 수 있습니다.
