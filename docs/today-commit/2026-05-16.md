zntc는 code splitting을 크게 넓혔습니다. 먼저 분할 청크마다 CSS를 나누고 content-hash와 `css_names` 패턴을 적용했으며, 동적 청크를 불러올 때 런타임에 CSS link 태그를 넣게 했습니다([#3322](https://github.com/ohah/zntc/pull/3322), [#3323](https://github.com/ohah/zntc/pull/3323), [#3325](https://github.com/ohah/zntc/pull/3325)). 작은 공통 청크를 합치는 `minChunkSize`([#3333](https://github.com/ohah/zntc/pull/3333))와 리터럴이 아닌 동적 `import()` 경고([#3336](https://github.com/ohah/zntc/pull/3336))가 이어졌고, Module Federation과 CJS·IIFE 분할 설계 RFC를 문서로 남겼습니다([#3319](https://github.com/ohah/zntc/pull/3319), [#3341](https://github.com/ohah/zntc/pull/3341)). 그 뒤 preserve-modules와 CJS 출력(P3-A, [#3343](https://github.com/ohah/zntc/pull/3343)), 레지스트리 런타임과 안정 모듈 ID를 쓰는 CJS·IIFE 분할(P3-B, [#3344](https://github.com/ohah/zntc/pull/3344), [#3346](https://github.com/ohah/zntc/pull/3346), [#3349](https://github.com/ohah/zntc/pull/3349)), UMD·AMD 분할([#3357](https://github.com/ohah/zntc/pull/3357)), IIFE 동적 로더의 worker·Deno·Node-ESM 폴백과 CSP nonce 지원([#3355](https://github.com/ohah/zntc/pull/3355), [#3358](https://github.com/ohah/zntc/pull/3358))이 차례로 병합됐고, 초기 레지스트리 코어는 걷어 내 하나로 정리했습니다(P3-C, [#3363](https://github.com/ohah/zntc/pull/3363)). 청크를 넘나드는 re-export와 `export *`, namespace re-export가 바인딩되지 않던 문제, 같은 청크 동적 import가 다시 쓰이지 않아 `ERR_MODULE_NOT_FOUND`가 나던 문제, 동적 entry 청크의 중복 export 오류, 중첩 namespace re-export 체인 모듈이 과하게 지워지던 문제([#3371](https://github.com/ohah/zntc/pull/3371)) 등 후속 수정도 같은 날 들어왔습니다.

다른 영역에서는 semantic 분석이 사용자 import를 호이스팅된 심볼로 미리 선언하도록 고쳐 export가 import 바인딩을 가리키는 문제를 정리했고([#3312](https://github.com/ohah/zntc/pull/3312), [#3314](https://github.com/ohah/zntc/pull/3314)), class 필드 이름 get/set, 삼항 결과 자리의 반환 타입 있는 화살표 함수, 파생 클래스 매개변수 프로퍼티 변환의 use-after-free([#3320](https://github.com/ohah/zntc/pull/3320))를 수정했습니다. Flow match 식은 스칼라 패턴과 객체·배열·인스턴스 구조 분해까지 정밀하게 변환하게 됐습니다([#3301](https://github.com/ohah/zntc/pull/3301), [#3304](https://github.com/ohah/zntc/pull/3304)). mangler는 RFC #3288 아래에서 측정과 예약 이름 전파를 이어 가다가, 검증으로 반박된 슬롯 공유 인프라를 제거했습니다([#3342](https://github.com/ohah/zntc/pull/3342)).
