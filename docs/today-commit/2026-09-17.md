## 요약 (AI 작성)

maru 편집기가 진단을 그리고 언어 서버에 붙은 날입니다. 전날 열린 [#3786](https://github.com/ohah/maru/pull/3786)이 병합돼 진단 층이 섰습니다. 첫 출처는 tree-sitter의 ERROR/MISSING 노드이고, 구문 오류가 gutter 글리프·지그재그 밑줄·막대와 미니맵 마커로 서며 F8/⇧F8로 오갑니다(§5.4). 실제 앱 캡처에서 뿌리 자체가 ERROR가 되면 파일 전체가 빨갛게 칠해지는 것을 보고, 뿌리는 진단으로 내지 않고 늘 내려가게 고쳤습니다. 이어 LSP seam 1단으로 transport·수명·신뢰 프롬프트·Full sync·publishDiagnostics 합치기·상태바 설치 안내를 세웠고([#3788](https://github.com/ohah/maru/pull/3788)), 프로그램이 닫은 모달을 거부로 기억하지 않게 하는 등 캡처가 잡은 셋을 고쳤습니다. 2단 ①로 포인터가 멈추면 진단 문장과 언어 서버 hover를 낱말 아래 상자로 보이는 호버 박스를 열었습니다(§8.2b, [#3789](https://github.com/ohah/maru/pull/3789)). 진단 줄을 VS Code 마커 호버 모양으로 맞추는 [#3790](https://github.com/ohah/maru/pull/3790)은 이날 PR이 열렸습니다.

zntc는 v0.1.8 릴리스 커밋을 냈습니다([#4657](https://github.com/ohah/zntc/pull/4657)). 그 전에 zntc.config의 alias를 app 빌드까지 배선하고 배열형 alias 디렉토리를 해석하게 했으며([#4652](https://github.com/ohah/zntc/pull/4652)), ESM-wrap의 named-local `export default`가 var/function을 이중 선언하던 것([#4653](https://github.com/ohah/zntc/pull/4653)), `export default`가 전역을 가리키면 splitting 청크가 깨지던 것과 onResolve의 `external: true`가 반영되지 않던 것([#4654](https://github.com/ohah/zntc/pull/4654)), `--outfile`/`--outdir`이 산출물 보류 게이트를 건너뛰던 것([#4655](https://github.com/ohah/zntc/pull/4655))을 고쳤습니다. v0.1.7 이후 모든 PR의 CI를 install 단계에서 죽이던 bun.lock과 stale TSC 스냅샷도 갱신했고([#4656](https://github.com/ohah/zntc/pull/4656)), 릴리스 뒤 bun.lock을 다시 동기화했습니다([#4658](https://github.com/ohah/zntc/pull/4658)). package.json `module` 필드 해석분에 Node CJS interop을 적용하지 않게 하는 [#4661](https://github.com/ohah/zntc/pull/4661)은 이날 열렸습니다.

공개 커밋 21개, 해당일 생성 또는 병합된 PR 12개를 정리했습니다. PR 생성 11개·병합 10개는 같은 PR이 양쪽에 포함될 수 있습니다.
