## 요약 (AI 작성)

maru는 사이드바에 claude·codex 에이전트 세션 카드를 띄우는 [#653](https://github.com/ohah/maru/pull/653)을 병합하고, 에이전트 세션 감지 설계 문서를 먼저 쓴 뒤 claude 트랜스크립트 상태 파싱 코어, codex 어댑터, 사이드바 상태 표시, 완료 알림을 차례로 넣었습니다. codex 어댑터를 기능 브랜치로 보낸 [#656](https://github.com/ohah/maru/pull/656)은 병합되지 않고 닫혔고, 같은 내용의 커밋은 main에 들어 있습니다. 이어 I/O와 렌더 스레드를 나누는 설계 문서와 함께 코어 락을 도입하고, 렌더 palette를 소유 복사로 바꾼 뒤 활성·비활성 pane 렌더, kitty 이미지, blink·스크롤바, 입력 리포트, 찾기 등 코어를 읽는 경로마다 락을 걸었습니다. 그 위에서 reader 스레드가 출력을 직접 코어에 적용하고 OSC 10·11, CPR, DA 응답을 렌더 tick과 무관하게 바로 돌려주게 해, 출력이 몰리는 codex 시작 중 응답이 늦어지던 문제를 풀었습니다. 키 입력 직후 크래시는 frame 조립의 락 io를 FrameLoop가 소유하도록 해 고쳤습니다.

codex 입력창이 회색으로 그려지지 않던 다른 원인은 빌드 환경의 `CLICOLOR_FORCE`·`FORCE_COLOR`가 자식 셸로 상속된 것이어서, 자식 env에서 이를 지우고 정책을 문서로 남겼습니다. box 선과 둥근 모서리의 중앙 정렬 계산도 통일했습니다. 스레딩 2단계로는 렌더 tick 없이 OSC 11 응답이 전달되는지, 출력 폭주 중 응답 지연 상한, 동시성 스트레스와 close 경합을 보는 회귀 테스트를 넣은 뒤, 입력 방향 bounded FIFO `PtyWriteQueue`와 통합 poll 루프로 reader 스레드를 PTY의 유일한 writer로 만들었고, 리뷰에서 나온 큐 간 데드락과 write 오류 누락을 고쳤습니다. 줄 가운데에서 한글을 조합할 때 뒤 글자를 가리던 문제는 조합 중 글자를 삽입형으로 미리 보여 주도록 바꿨습니다([#674](https://github.com/ohah/maru/pull/674)).

iris는 strict HBC 엔진 비교 POC를 넓히고([#41](https://github.com/ohah/iris/pull/41)) global 접근 진단 벤치마크를 더한 뒤, 전역·객체 프로퍼티 operand 캐시([#43](https://github.com/ohah/iris/pull/43), [#44](https://github.com/ohah/iris/pull/44)), 객체 프로퍼티 쓰기 조회 최적화([#48](https://github.com/ohah/iris/pull/48)), 숫자 equality jump와 NativeMath Call2 fast path([#49](https://github.com/ohah/iris/pull/49), [#51](https://github.com/ohah/iris/pull/51)), Math 조회 페어, 전역·객체 숫자 갱신, 나머지 누적, 체크섬, Uint8 인덱스 쓰기 시퀀스의 빠른 경로([#54](https://github.com/ohah/iris/pull/54)부터 [#63](https://github.com/ohah/iris/pull/63)까지)를 추가했습니다. 효과가 없던 후보들은 제외 결과로 기록해 두었고, 이날 연 iris PR 28개는 모두 병합됐습니다. 블로그 저장소에는 오늘의 커밋 요약과 크론 교정 커밋이 올라갔습니다.
