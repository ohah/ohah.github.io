# 2026-04-22

> 날짜는 UTC 기준으로 나눴습니다(9월 22일부터는 한국 시간 기준). 커밋은 커미터 시각(committer date), PR은 생성·병합 시각으로 분류했습니다. 목록은 2026-10-06 KST에 GitHub에서 다시 조회해 보강했습니다. 공개 저장소의 기본 브랜치 활동만 포함합니다.

## 요약 (AI 작성)

zntc는 전날 만든 profile 인프라로 병목을 쪼개 보며 성능을 손봤습니다. scanner·resolve 단계 타이머와 graph·emit 내부 하위 단계를 추가했고([#1716](https://github.com/ohah/zntc/pull/1716), [#1718](https://github.com/ohah/zntc/pull/1718), [#1724](https://github.com/ohah/zntc/pull/1724)~[#1726](https://github.com/ohah/zntc/pull/1726)), `phaseDurations`의 레거시 이름을 실제 의미에 맞게 바꿨습니다(BREAKING, [#1719](https://github.com/ohah/zntc/pull/1719)). Zig 0.15.2 x86_64의 `@memset` 인코더 버그 우회([#1715](https://github.com/ohah/zntc/pull/1715)), WASM의 `clock_time_get` WASI stub([#1717](https://github.com/ohah/zntc/pull/1717)), lightningcss 타입 선언으로 tsc 빌드 회복([#1723](https://github.com/ohah/zntc/pull/1723))도 이어졌습니다.

HMR 경로에서는 Metro처럼 요청 시점에 소스맵을 만드는 lazy sourcemap 인프라와 NAPI getter를 넣고([#1728](https://github.com/ohah/zntc/pull/1728), [#1729](https://github.com/ohah/zntc/pull/1729)), 모듈별 HMR 코드에 `//# sourceURL` 주석을 붙였으며([#1730](https://github.com/ohah/zntc/pull/1730)), watcher가 알려 준 변경 파일만 stat하는 mtime 캐시([#1732](https://github.com/ohah/zntc/pull/1732))와 출력 버퍼 사전 할당([#1731](https://github.com/ohah/zntc/pull/1731))을 더했습니다. 라이브러리 번들링 속도는 link·metadata 하위 단계 측정으로 effect의 namespace rewrite 병목을 찾아 캐시를 Linker로 올리고 namespace 접근 인덱스를 공유했으며([#1738](https://github.com/ohah/zntc/pull/1738)~[#1740](https://github.com/ohah/zntc/pull/1740)), package.json type 필드를 캐시해 date-fns가 esbuild 대비 13배에서 4배 수준으로 줄었다고 PR에 적었습니다([#1743](https://github.com/ohah/zntc/pull/1743), [#1745](https://github.com/ohah/zntc/pull/1745)).

minify 쪽은 런타임 헬퍼 29개의 이름 축약([#1750](https://github.com/ohah/zntc/pull/1750))과 헬퍼 이름 표의 공용 모듈 분리([#1753](https://github.com/ohah/zntc/pull/1753))를 넣었고, RN과 minify를 함께 쓸 때의 연쇄 크래시와 문법 오류 네 가지([#1751](https://github.com/ohah/zntc/pull/1751)), 축약 generator 런타임의 닫는 중괄호 누락([#1755](https://github.com/ohah/zntc/pull/1755)), `__generator` 함수 이름의 symbol_id 전파([#1756](https://github.com/ohah/zntc/pull/1756)), 중첩 mangler가 최상위 canonical 이름과 겹치던 문제([#1758](https://github.com/ohah/zntc/pull/1758))를 고쳤습니다. 이어 `--mangle-report` 측정 하네스를 만들고, 최상위와 중첩으로 나뉘어 있던 mangler를 하나의 `mangleAll`로 합치는 작업을 단계별로 병합했습니다([#1761](https://github.com/ohah/zntc/pull/1761)~[#1766](https://github.com/ohah/zntc/pull/1766)). Windows CI는 GitHub runner 메모리 부족으로 Debug 빌드를 건너뜁니다([#1746](https://github.com/ohah/zntc/pull/1746)).

bungae는 ZTS의 새 profile 필드에 맞춰 HMR 소요 시간 breakdown을 여러 줄로 보여 주고 graph·emit 하위 단계까지 출력하게 했으며([#63](https://github.com/ohah/bungae/pull/63)~[#67](https://github.com/ohah/bungae/pull/67)), dev 서버에 lazy sourcemap 라우트와 빌드 단위 캐시를 붙이고 HMR 업데이트에는 sourceMappingURL만 달도록 바꿨습니다([#68](https://github.com/ohah/bungae/pull/68), [#69](https://github.com/ohah/bungae/pull/69)). ohah.github.io에는 4월 22일 요약과 맞춤법 크론 커밋이 올라왔습니다.

공개 커밋 69개, 해당일 생성 또는 병합된 PR 47개를 정리했습니다. PR 생성 47개·병합 46개는 같은 PR이 양쪽에 포함될 수 있습니다.
