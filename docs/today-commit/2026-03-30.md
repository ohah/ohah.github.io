> 날짜는 UTC 기준으로 나눴습니다(9월 22일부터는 한국 시간 기준). 커밋은 커미터 시각(committer date), PR은 생성·병합 시각으로 분류했습니다. 목록은 2026-10-06 KST에 GitHub에서 다시 조회해 보강했습니다. 공개 저장소의 기본 브랜치 활동만 포함합니다.

## 요약 (AI 작성)

zntc는 번들 `--watch` 모드와 플러그인 재사용([#531](https://github.com/ohah/zntc/pull/531))으로 하루를 시작해, dev server에서도 플러그인을 쓰게 하고([#535](https://github.com/ohah/zntc/pull/535)) 플러그인 API를 Vite·Rollup 스타일로 바꿨습니다([#537](https://github.com/ohah/zntc/pull/537)). dev server는 기본 포트 12300과 host·open 옵션, API 프록시 `--proxy`([#538](https://github.com/ohah/zntc/pull/538), [#539](https://github.com/ohah/zntc/pull/539))와 통합 테스트 8개를 갖췄고, CI에서 불안정한 `--serve --plugin` 테스트는 건너뛰도록 했습니다. 이어 `zts.config` 파일 자동 감지([#545](https://github.com/ohah/zntc/pull/545)), `renderChunk`·`generateBundle` 훅과 설정 변경 시 재시작([#547](https://github.com/ohah/zntc/pull/547)), `@zts/core`의 TypeScript 전환([#548](https://github.com/ohah/zntc/pull/548)), load 훅의 loader 필드([#550](https://github.com/ohah/zntc/pull/550)), Vite·esbuild 호환 `defineConfig` 빌드 옵션([#551](https://github.com/ohah/zntc/pull/551))이 들어왔습니다. 오후에는 소스맵 정확도 개선과 네이티브 파일 감시, 증분 빌드([#553](https://github.com/ohah/zntc/pull/553))를 넣고, Linux의 inotify 감시를 `CLOSE_WRITE`와 디렉터리 감시로 바꿔 HMR을 안정화했습니다([#554](https://github.com/ohah/zntc/pull/554), [#556](https://github.com/ohah/zntc/pull/556)).

저녁부터는 Flow 지원을 시작했습니다. `@flow` pragma 감지와 `--flow` 옵션([#558](https://github.com/ohah/zntc/pull/558)), 기본 타입 파싱과 타입 제거([#561](https://github.com/ohah/zntc/pull/561)), opaque type과 variance([#562](https://github.com/ohah/zntc/pull/562)), `import typeof`, declare·interface, `as` 식을 차례로 병합했고, Metro의 `@flow` 파일 410개를 통과하는 스모크 테스트를 추가했습니다([#567](https://github.com/ohah/zntc/pull/567)). 기능 브랜치에 쌓았던 [#559](https://github.com/ohah/zntc/pull/559), [#560](https://github.com/ohah/zntc/pull/560)은 닫고 같은 내용을 main 대상 PR로 다시 올린 것입니다. 밤에는 주석 형식의 Flow 타입, TypeCast·exact object·`%checks`([#568](https://github.com/ohah/zntc/pull/568), [#570](https://github.com/ohah/zntc/pull/570))와 React Native용 `--resolve-extensions`·`--main-fields` 옵션([#573](https://github.com/ohah/zntc/pull/573))을 넣고 문서에 Flow 완료를 반영했습니다.

멀티 백엔드 데스크톱 프레임워크 suji가 이날 첫 커밋을 올렸습니다. 설정 파서와 `dev`·`build`·`run` CLI, 프로젝트를 만드는 `suji init`을 만들고, 설정은 TOML을 빼고 JSON만 쓰기로 했습니다. `#[suji::command]` 매크로를 쓰는 Rust SDK, 구조체 바인딩 방식의 Go SDK, comptime 빌더와 dlopen으로 붙는 Zig 백엔드, 코어의 이벤트 pub/sub과 JS 브리지를 추가했으며, 백엔드 간 호출과 부하 데모를 거쳐 API를 Electron식 `handle`·`invoke`·`on`·`send`로 정리했습니다. 세 SDK 모두에 `on`·`off`를 구현하고 Go는 C 브리지로 이벤트 버스에 연결해 Phase 1을 완료로 표시했습니다. 이 저장소는 PR 없이 커밋으로 진행됐습니다.

공개 커밋 86개, 해당일 생성 또는 병합된 PR 45개를 정리했습니다. PR 생성 45개·병합 43개는 같은 PR이 양쪽에 포함될 수 있습니다.
