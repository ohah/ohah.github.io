## 요약 (AI 작성)

zntc는 진단과 옵션 전달 구조를 다듬는 것으로 시작했습니다. 재선언·참조 에러가 원래 선언이나 정의 위치를 보조 라벨로 가리키게 하고([#1439](https://github.com/ohah/zntc/pull/1439), [#1440](https://github.com/ohah/zntc/pull/1440)), 모든 진단에 수정 힌트와 문서 URL을 붙였습니다([#1441](https://github.com/ohah/zntc/pull/1441), [#1442](https://github.com/ohah/zntc/pull/1442)). WASM/NAPI 진입점이 옵션을 필드별 인자로 받던 구조를 JSON 페이로드로 바꾸고([#1445](https://github.com/ohah/zntc/pull/1445)), comptime reflection으로 `TranspileOptions` JSON 스키마를 생성해 `$schema` 자동 완성이 되는 `zts.config.json` 자동 로드를 붙였으며([#1446](https://github.com/ohah/zntc/pull/1446), [#1447](https://github.com/ohah/zntc/pull/1447)), Zig와 TS 옵션 필드의 동기화를 테스트로 검증합니다([#1448](https://github.com/ohah/zntc/pull/1448)). JS 플러그인 실행은 subprocess 경로를 없애고 NAPI로 단일화했습니다([#1450](https://github.com/ohah/zntc/pull/1450)).

안정성 항목으로 Chrome DevTools 소스맵 E2E, watch/serve 150회 연속 재빌드 메모리 스트레스, vite-plugin-zts로 만든 Vite 앱의 브라우저 실행 E2E를 추가했습니다([#1451](https://github.com/ohah/zntc/pull/1451)~[#1453](https://github.com/ohah/zntc/pull/1453)). 설계 문서는 `docs/`로 옮기고 README를 갱신했으며([#1449](https://github.com/ohah/zntc/pull/1449)), ISSUES.md의 미해결 항목은 GitHub Issues로 넘겼습니다([#1458](https://github.com/ohah/zntc/pull/1458)). ESM+Node 출력에 CJS 래퍼가 있으면 `createRequire` shim을 넣고([#1459](https://github.com/ohah/zntc/pull/1459)), rest 파라미터를 함수 스코프에 등록하지 않던 버그([#1460](https://github.com/ohah/zntc/pull/1460))를 계기로 binding 위치의 rest를 `rest_element` 태그로 통일하고 walker들을 새 헬퍼로 옮겼습니다([#1461](https://github.com/ohah/zntc/pull/1461), [#1463](https://github.com/ohah/zntc/pull/1463), [#1466](https://github.com/ohah/zntc/pull/1466)).

나머지는 다운레벨링 엣지 케이스 정리였습니다. 엣지 케이스 테스트 83건을 추가하면서 정규식 `\k<name>` 변환을 고쳤고([#1474](https://github.com/ohah/zntc/pull/1474)), `delete obj?.a?.b`가 실제로 지우지 않던 문제([#1476](https://github.com/ohah/zntc/pull/1476)), const enum 멤버 참조 인라인([#1477](https://github.com/ohah/zntc/pull/1477)), named group 제거 시 `String.replace`의 `$<name>` 변환([#1478](https://github.com/ohah/zntc/pull/1478)), ES5 클래스의 parameter property([#1479](https://github.com/ohah/zntc/pull/1479))를 바로잡았습니다. private field는 static 복합 대입, `??=` 같은 논리 대입, `**=`, 대입식 반환값, 구조 분해 대상, optional chain 읽기, for-of/for-in 바인딩, 파생 클래스의 `super()` 뒤 초기화, `new this.#priv.method()`까지 연달아 고쳤습니다([#1482](https://github.com/ohah/zntc/pull/1482), [#1484](https://github.com/ohah/zntc/pull/1484), [#1487](https://github.com/ohah/zntc/pull/1487), [#1489](https://github.com/ohah/zntc/pull/1489), [#1490](https://github.com/ohah/zntc/pull/1490), [#1493](https://github.com/ohah/zntc/pull/1493), [#1494](https://github.com/ohah/zntc/pull/1494), [#1496](https://github.com/ohah/zntc/pull/1496), [#1518](https://github.com/ohah/zntc/pull/1518)). generator의 `yield*` 대입과 레이블 없는 break/continue([#1498](https://github.com/ohah/zntc/pull/1498), [#1499](https://github.com/ohah/zntc/pull/1499)), 계산된 키 객체의 getter/setter 누락([#1501](https://github.com/ohah/zntc/pull/1501)), ES5 타깃에서 Stage 3 데코레이터가 조용히 사라지던 문제와 MobX 회귀 테스트([#1503](https://github.com/ohah/zntc/pull/1503), [#1504](https://github.com/ohah/zntc/pull/1504)), 다른 모듈에서 import한 데코레이터가 tree shaking으로 빠지던 문제([#1505](https://github.com/ohah/zntc/pull/1505)), ES5 클래스 멤버 주석 위치([#1515](https://github.com/ohah/zntc/pull/1515), [#1517](https://github.com/ohah/zntc/pull/1517))도 이날 병합됐습니다.
