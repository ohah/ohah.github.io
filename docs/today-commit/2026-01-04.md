## 요약 (AI 작성)

chrome-remote-devtools는 React Native inspector의 네트워크 훅을 다듬는 PR 다섯 개를 병합했습니다. 전날 연 [#50](https://github.com/ohah/chrome-remote-devtools/pull/50)은 ConsoleHook·NetworkHook을 전역 변수·유틸리티·이벤트 전송 단위의 작은 파일로 나누고, 응답 데이터 맵을 mutex로 보호했습니다. [#53](https://github.com/ohah/chrome-remote-devtools/pull/53)은 JSI 훅으로 대체된 iOS·Android의 죽은 코드를 지우고 C++ 훅에 저장된 응답 본문으로 `Network.getResponseBody`를 지원했으며, 읽은 응답을 지워 메모리 누수를 막고 Android에서 UTF-8 검증과 바이너리 base64 대체를 넣었습니다. React Native가 fetch를 XMLHttpRequest로 감싼다는 점을 근거로 fetch 훅을 빼고 XHR 훅만 쓰는 정리도 이 흐름에 들어갔습니다.

inspector의 클라이언트 표는 웹과 React Native 클라이언트를 한 표에서 유형 아이콘으로 구분해 보여 주도록 합쳤고([#52](https://github.com/ohah/chrome-remote-devtools/pull/52)), Client 타입을 WebClient와 ReactNativeClient로 나눴습니다. XHR 훅은 `addEventListener`로 원래 동작을 보존하고 HEADERS_RECEIVED 시점에 응답 헤더를 모으며, `getAllResponseHeaders` 호출의 this 바인딩과 blob 응답 처리를 고쳤습니다([#54](https://github.com/ohah/chrome-remote-devtools/pull/54)). 이어 XHR 상태 0과 fetch 실패를 네트워크 오류로 보고해 DevTools 네트워크 탭에 표시되게 하고, Android JNI의 promise 수명 관리와 경쟁 조건을 손봤습니다([#57](https://github.com/ohah/chrome-remote-devtools/pull/57)).

콘솔·네트워크 훅을 켜고 끄는 JavaScript·네이티브 API와 플로팅 버튼을 추가했고, React Native 예제 앱은 콘솔·네트워크 탭 구조로 나누고 fetch와 XHR 상태를 따로 표시하도록 바꿨습니다. `AGENTS.MD`에는 JSI 수준에서 이벤트를 가로채는 React Native 원격 디버깅 전략을 정리했습니다.

공개 커밋 25개, 해당일 생성 또는 병합된 PR 5개를 정리했습니다. PR 생성 4개·병합 5개는 같은 PR이 양쪽에 포함될 수 있습니다.
