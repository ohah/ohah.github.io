## 요약 (AI 작성)

chrome-remote-devtools는 예제 앱의 Metro 설정에서 `react`와 `react-native`를 앱 루트에서만 해석하도록 해 작업 공간 패키지가 React를 두 번 불러오던 문제를 고쳤습니다([#116](https://github.com/ohah/chrome-remote-devtools/pull/116)). 서버의 `metro_proxy_handler`는 핸들러와 URL 재작성 모듈로 나눴고([#117](https://github.com/ohah/chrome-remote-devtools/pull/117)), 연결 관리자를 연결 ID로 조회하도록 고쳤습니다([#118](https://github.com/ohah/chrome-remote-devtools/pull/118)). Metro 소스맵 파일 요청을 Metro로 넘기는 경로를 추가하고, 앱이 나중에 연결돼도 Metro 프록시를 거친 Redux가 새로고침 없이 동작하게 했습니다.

`react-native-inspector`는 `scriptURL`로 Metro 실행인지 릴리스 빌드인지 판별해 Metro 모드에서는 콘솔·네트워크 훅을 끄도록 했고, `reconnect()`를 추가해 Metro 프록시 연결 시 자동으로 주입되게 했습니다. 소스맵을 직접 가져와 캐시하던 코드와 `CDPMessageHandler` 디버그 로그는 지웠으며, 인스펙터의 Profilers 모드를 없애고 Metro 탭이 기본으로 자체 인스펙터 화면을 열게 했습니다.

react-native-mcp 저장소는 이날 MCP 서버 패키지와 oxlint·oxfmt·mise 설정을 담은 초기 커밋으로 시작했습니다. README 패키지 구조와 커밋·PR 규칙을 정리하는 [#1](https://github.com/ohah/react-native-mcp/pull/1)도 이날 열렸습니다.
