## 요약 (AI 작성)

electron-mcp-server는 패키지 이름을 `@ohah/electron-mcp-server`로 바꾸고 데모 앱에 Vite dev 서버·HMR·preload 경로·CSP를 넣은 [#4](https://github.com/ohah/electron-mcp-server/pull/4)를 병합한 뒤, 도구 중심 구조로 리팩터링하면서 Chrome DevTools MCP 로드맵의 도구를 스텁으로 등록했습니다([#5](https://github.com/ohah/electron-mcp-server/pull/5)). 이후 페이지 컨텍스트에서 JS를 실행하는 `evaluate_script`([#7](https://github.com/ohah/electron-mcp-server/pull/7)), Chrome DevTools MCP와 같은 방식으로 요청을 상시 수집하는 `list_network_requests`·`get_network_request`([#8](https://github.com/ohah/electron-mcp-server/pull/8)), `list_pages`·`select_page`·`navigate_page`·`wait_for` 같은 내비게이션 도구([#9](https://github.com/ohah/electron-mcp-server/pull/9))를 차례로 구현하고 데모 E2E 테스트를 붙였습니다. 도구 스펙을 Chrome DevTools MCP와 같게 맞춘다는 규칙도 문서에 넣었습니다.

스크린샷은 Playwright `connectOverCDP`가 실패하는 문제로 CDP `Page.captureScreenshot`만 쓰게 고쳤다가 `take_screenshot`을 빼고 `take_snapshot`만 남겼고([#6](https://github.com/ohah/electron-mcp-server/pull/6)), 뒤이어 `take_screenshot`을 다시 추가하면서 hover·drag를 개선했습니다([#10](https://github.com/ohah/electron-mcp-server/pull/10)). `handle_dialog`는 Electron 원격 환경에서 `Page.handleJavaScriptDialog`가 동작하지 않아 등록을 막았습니다. SDK `registerTool` 제네릭이 Zod 스키마와 얽혀 생기던 타입 오류도 래퍼로 해결했습니다.

chrome-remote-devtools는 React Native 인스펙터의 AsyncStorage 기반 기기 ID를 없애고, 선택적인 `deviceId`를 받되 없으면 UUID를 만드는 방식으로 바꿨습니다([#110](https://github.com/ohah/chrome-remote-devtools/pull/110)). 예제 앱은 `react-native-device-info`의 `getUniqueId()`를 쓰고, 클라이언트 목록에는 RN 기기의 deviceId를 표시합니다. MMKV 보기에서 적용 바와 검증을 없애 편집이 바로 반영되게 한 [#109](https://github.com/ohah/chrome-remote-devtools/pull/109), 외부 링크를 `tauri-plugin-opener`로 열게 한 [#111](https://github.com/ohah/chrome-remote-devtools/pull/111)도 병합했고, MMKV v3·v4 인스턴스를 모두 받도록 고쳤습니다.

ohah.github.io에는 월간 오픈소스에 CRD(Chrome Remote Debugger) 카테고리를 추가해 개발 배경·기술 스택·개발 과정 문서 구조를 잡고, 개발 배경 문단을 다듬었습니다.

공개 커밋 49개, 해당일 생성 또는 병합된 PR 10개를 정리했습니다. PR 생성 8개·병합 10개는 같은 PR이 양쪽에 포함될 수 있습니다.
