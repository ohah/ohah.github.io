## 요약 (AI 작성)

zntc는 빌드 결과가 바이트 단위로 같게 나오는지 10회 반복으로 검사하는 결정성 게이트와 CI job을 먼저 세우고([#3565](https://github.com/ohah/zntc/pull/3565)), 모듈 인덱스 부여, mangler 후보 정렬, 이름 충돌 해결의 `NameOwner` 정렬, `exec_index` 동률 처리, emit 경로의 hashmap 순회, 치명적 진단 출력 순서를 모두 경로 기준의 안정된 순서로 바꿨습니다([#3566](https://github.com/ohah/zntc/pull/3566), [#3567](https://github.com/ohah/zntc/pull/3567), [#3568](https://github.com/ohah/zntc/pull/3568), [#3569](https://github.com/ohah/zntc/pull/3569), [#3570](https://github.com/ohah/zntc/pull/3570), [#3571](https://github.com/ohah/zntc/pull/3571)). 재번호 매김 때 `SymbolRef.module`을 다시 매핑하지 않아 생긴 모듈 간 심볼 해석 문제는 바로 hotfix했습니다([#3583](https://github.com/ohah/zntc/pull/3583)).

이어 한 번의 빌드에서 여러 포맷을 내보내는 다중 포맷 출력을 쌓았습니다. 링커 메타데이터에 포맷을 전달하고 emit마다 상태를 초기화하는 진입점을 둔 뒤, `OutputConfig`와 `BundleOptions.output` 배열, 다중 포맷 emit 루프, 동등성·순서 불변·메모리 안전 게이트를 거쳐([#3576](https://github.com/ohah/zntc/pull/3576), [#3577](https://github.com/ohah/zntc/pull/3577), [#3578](https://github.com/ohah/zntc/pull/3578)) rollup 방식의 `zntc(input).write(output).close()` API([#3579](https://github.com/ohah/zntc/pull/3579))와 esbuild 방식의 `build` 함수 `output` 배열 문법([#3585](https://github.com/ohah/zntc/pull/3585))을 추가했습니다. Module Federation과 다중 포맷을 함께 쓰는 설정은 거부하고([#3582](https://github.com/ohah/zntc/pull/3582)), 공유 에셋 정책은 문서와 CSS 테스트로 정했습니다.

오후에는 증분 리빌드 측정 인프라를 만들고 M0부터 M8까지 단계별로 프로파일 구간을 쪼갠 뒤, export 이름 인덱스 사전 계산과 호출부 이전([#3593](https://github.com/ohah/zntc/pull/3593), [#3594](https://github.com/ohah/zntc/pull/3594)), re-export 진입의 스택 버퍼, `RequestedExports.names`의 HashMap을 평탄한 배열로 바꾸는 변경([#3599](https://github.com/ohah/zntc/pull/3599)), 의존성 배열 용량 예약, 모듈 경로용 arena allocator([#3602](https://github.com/ohah/zntc/pull/3602))로 그래프 처리를 줄였습니다. 문서 사이트에는 `/llms.txt`·`/llms-full.txt` 엔드포인트와 Claude Code용 zntc-cli 스킬을 추가해 영어로 통일하고 간소화했습니다([#3604](https://github.com/ohah/zntc/pull/3604), [#3605](https://github.com/ohah/zntc/pull/3605), [#3606](https://github.com/ohah/zntc/pull/3606)).

밤에는 RN 수정을 대거 묶은 ESM re-export getter PR([#3542](https://github.com/ohah/zntc/pull/3542))이 병합됐습니다. 여기에는 pnpm 심링크 모듈 정규화, Hermes용 미해결 dynamic import 낮추기, styled-components 처리의 Metro 정렬, scale 전용 에셋 해석, 엄격 순서에서 inline require 보존, throw 뒤 CJS factory 재시도, TSX generic JSX 속성 보존 등이 들어 있습니다. 헤드리스 Chromium으로 런타임을 확인하는 `zntc verify --browser` CLI([#3609](https://github.com/ohah/zntc/pull/3609))와 이를 에이전트가 부를 수 있는 `verify_in_chrome` MCP 도구([#3610](https://github.com/ohah/zntc/pull/3610)), dev overlay 클라이언트의 `.js` 파일 분리([#3608](https://github.com/ohah/zntc/pull/3608)), Electron 타깃별 config 예제 문서([#3563](https://github.com/ohah/zntc/pull/3563))도 병합됐습니다. 블로그 저장소 ohah.github.io의 커밋 14개는 크론의 문서 점검 표시와 요약 갱신 커밋입니다.

공개 커밋 86개, 해당일 생성 또는 병합된 PR 46개를 정리했습니다. PR 생성 44개·병합 46개는 같은 PR이 양쪽에 포함될 수 있습니다.
