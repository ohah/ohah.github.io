zntc는 전날 열린 진단 게이트 [#4264](https://github.com/ohah/zntc/pull/4264)를 병합하고 ES2025 정규식 `(?s:…)`, `(?i:…)`, `(?m:…)` modifier 다운레벨([#4265](https://github.com/ohah/zntc/pull/4265)부터 [#4267](https://github.com/ohah/zntc/pull/4267)까지)을 완성했습니다. 이후 70개 가까운 커밋으로 저장소 전반의 결함을 정리했는데, 번들러의 ModuleKey 스택 버퍼 오버플로와 minify·bundler의 UAF, napi 오류 경로의 자원 누수, dev 서버 WS writer 데이터 경합과 프록시 바디 미전달, generator 라벨 `continue`와 for-in 의미 위반, v 플래그 집합 연산을 합집합으로 바꾸던 정규식 문제([#4308](https://github.com/ohah/zntc/pull/4308)), mangler가 `eval`을 이름으로 배정하던 문제([#4313](https://github.com/ohah/zntc/pull/4313)), lexer의 BOM·UTF-8 검증, sourcemap VLQ의 정수 오버플로, React Native `open-url` 입력 검증, CLI 플래그와 BuildOptions 스키마 불일치([#4310](https://github.com/ohah/zntc/pull/4310)) 등이 포함됐습니다. 성능 쪽에서는 기본 worker 풀을 8개로 제한하고([#4359](https://github.com/ohah/zntc/pull/4359)), 의존 export 요청과 top-level 이름 순회를 O(N²)에서 O(N)으로 줄였습니다([#4406](https://github.com/ohah/zntc/pull/4406), [#4407](https://github.com/ohah/zntc/pull/4407)). 같은 주제의 [#4300](https://github.com/ohah/zntc/pull/4300), [#4336](https://github.com/ohah/zntc/pull/4336)은 병합되지 않고 닫혔습니다.
