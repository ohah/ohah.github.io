## 요약 (AI 작성)

zntc는 RN codegen 마무리와 타입 전용 import 정리로 시작했습니다. prop 위치에 남은 Flow·TS 타입 노드를 `mixed`로 매핑하고([#2452](https://github.com/ohah/zntc/pull/2452)), Flow enum을 `flow-enums-runtime` 호출로 바꾸면서 번들러가 그 runtime require를 다시 쓰도록 고쳤으며([#2465](https://github.com/ohah/zntc/pull/2465)), `require.context` 모듈 ID에 rootDir을 적용했습니다([#2478](https://github.com/ohah/zntc/pull/2478)). `import { type A, type B }` 선언을 통째로 지우고, 해석되지 않는 타입 전용 import는 빌드를 실패시키지 않으며, 타입 전용 import 생략에 걸려 있던 16개 바인딩 상한을 없앴습니다([#2467](https://github.com/ohah/zntc/pull/2467), [#2468](https://github.com/ohah/zntc/pull/2468), [#2469](https://github.com/ohah/zntc/pull/2469), [#2479](https://github.com/ohah/zntc/pull/2479)). HMR은 reparse 경로를 절대 경로 대신 모듈 ID로 다루게 됐습니다([#2480](https://github.com/ohah/zntc/pull/2480)).

안전성 점검도 이어졌습니다. 스택 크기에 묶인 버퍼가 조용히 잘리던 transformer 세 경로와 AST walker·catch 이름 수집을 동적 배열로 바꾸고([#2476](https://github.com/ohah/zntc/pull/2476), [#2482](https://github.com/ohah/zntc/pull/2482)), catch 바인딩의 binding_property 처리([#2485](https://github.com/ohah/zntc/pull/2485)), worklet의 깊이 제한 재귀 탐색을 명시적 스택으로 바꾸는 수정([#2486](https://github.com/ohah/zntc/pull/2486))이 들어갔습니다. minifier는 한 번만 쓰는 최상위 const의 inline 순서를 바로잡았고([#2495](https://github.com/ohah/zntc/pull/2495)), NAPI build 옵션 slice 해제도 보강했습니다([#2499](https://github.com/ohah/zntc/pull/2499)).

나머지는 대부분 번들러 성능 작업입니다. 전날 열린 graph 탐색 read/stat 비용 개선([#2440](https://github.com/ohah/zntc/pull/2440))이 소스 읽기와 mtime stat을 합치는 형태로 병합됐고, 미사용 define 사전 패스, Worker 레코드 스캔, 경로 import의 builtin 검사, 할 일 없는 builtin 플러그인 hook을 건너뛰게 했습니다([#2481](https://github.com/ohah/zntc/pull/2481), [#2487](https://github.com/ohah/zntc/pull/2487), [#2488](https://github.com/ohah/zntc/pull/2488), [#2490](https://github.com/ohah/zntc/pull/2490)). AST의 `addString` 저장을 중복 제거하고 intern 적중 통계와 Span 키 HashMap을 붙인 뒤([#2496](https://github.com/ohah/zntc/pull/2496), [#2498](https://github.com/ohah/zntc/pull/2498), [#2500](https://github.com/ohah/zntc/pull/2500)), transformer의 AccessorSpans·styled-components·define span 캐시를 이 intern map으로 흡수했습니다([#2501](https://github.com/ohah/zntc/pull/2501), [#2510](https://github.com/ohah/zntc/pull/2510), [#2515](https://github.com/ohah/zntc/pull/2515)). tree-shaking은 숫자 상수 체인을 접고([#2497](https://github.com/ohah/zntc/pull/2497)) 역의존 탐색, pre-shake 갱신 범위, 상수 판정 캐시, `Symbol.const_value` 분리, 숫자 심볼 bitset으로 그 비용을 줄였습니다([#2509](https://github.com/ohah/zntc/pull/2509), [#2511](https://github.com/ohah/zntc/pull/2511), [#2513](https://github.com/ohah/zntc/pull/2513), [#2514](https://github.com/ohah/zntc/pull/2514), [#2516](https://github.com/ohah/zntc/pull/2516)). 프로파일 계측 세분화, median 기반 벤치마크 리포트와 대형 monorepo 번들 측정([#2492](https://github.com/ohah/zntc/pull/2492), [#2493](https://github.com/ohah/zntc/pull/2493)), CLI의 debug·resolver 옵션 노출과 문서 동기화([#2491](https://github.com/ohah/zntc/pull/2491), [#2494](https://github.com/ohah/zntc/pull/2494))도 있었습니다. core-js 런타임 폴리필 지원 [#2517](https://github.com/ohah/zntc/pull/2517)은 이날 열려 5월 4일에 병합됐습니다.
