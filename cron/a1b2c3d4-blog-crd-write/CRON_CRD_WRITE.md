# Blog-CRD-Write Cron Job

## Purpose
Automated weekly structured summary of blog content, using CR (Chronicle Reference Document) format.

### What is a "C RD Doc"?
Short for Chronicle Record. A one-page reference that captures:

1. **What happened** - Key updates/events this week in brief narrative form.
2. **Why it matters** - Strategic context and impact on the blog/identity/persona over time, not just features shipped or metrics met.

Format: 3-7 paragraphs of clear writing without markdown styling unless needed for emphasis (bolding only), single column text body with optional section headings if helpful; keep to one page max. Avoid lists where possible—paragraph flow is more important than bullet points when summarizing weeks and explaining significance, though minimal structured context can help readability.

CRDs serve as both an archive record of what occurred each week AND a source for future content (posts or marketing copy) by synthesizing weekly work into concise narratives with clear value propositions. They should be timeless: referenceable months/years later without needing additional background explanation from the requester, making them useful beyond immediate utility.

## Input Sources
- Git repository changes in workspace `/Users/yoonhb/Documents/workspace/blog`
- Recent commit history (last 7 days)
- Memory files (`memory/YYYY-MM-DD.md` and `MEMORY.md`)
- Current time: Wednesday July 29th. If today is Tuesday or earlier, include partial week up to present; otherwise treat as full weekly summary including recent updates.

## Output Format
One CRD document per cron run:
```
{week_identifier}-crd-write-{YYYY-MM-DD}.md

# {Week Title}

1-3 sentences: Week context + key theme in brief.
Then 2 paragraphs (or up to ~10 lines if content is dense) about what happened and why it matters, not just metrics met. Then one paragraph focusing on strategic impact—how this shapes the blog's direction over time—noting any lessons learned or important decisions made.

If a summary for week ending {last_date} was already written (check files in cron/a1b2c3d4-blog-crd-write/), mention it by title and optionally add brief updates since then.
```

Example:
```markdown
# Week 30 Summary - July

This is the inaugural CRD document establishing weekly structured summaries for blog content creation. The week focused on setting up automated documentation workflows using cron jobs to generate chronicle records each cycle.

Building out a consistent output format was essential—this won't be just another todo list but something referenceable months from now, useful as both an archive record of what occurred and source material for future posts or marketing copy that captures the blog's evolution over time. The first summaries will cover weeks ending on specific dates to track momentum while establishing patterns.

The workflow uses cron with Asia/Seoul timezone scheduling; each run generates a one-page CRD document in markdown format without bullet-point overload—paragraph flow communicates better than lists when telling weekly stories and explaining significance, though minimal structure helps readability. The first summaries will cover weeks ending on specific dates to establish the pattern before full automated execution.

---

Generated by blog-crd-write cron job
```

### File Existence Check Before Writing:
Before creating a new CRD, check if one already exists in the cron directory matching this pattern. If it does exist and covers approximately same time period (~3-7 days), skip creation—assume job completed.
